# 菜单分段与交互展开漏译：测试范围

## 改动范围

- 修复 `inline-block` 容器内多个块级内容被合并翻译、译文集中插入末尾的问题，包含嵌套包装层。
- 共用页面扫描增加交互后的可见性检查，覆盖 hover、焦点、原生展开状态、CSS 过渡和动画。
- 自身及祖先的 class、style、hidden 等变化继续通过 DOM 观察处理；动态插入内容继续沿用已有流程。
- 本次没有增加 THAITICKETMAJOR 专属规则。应做跨站回归，不能只验证该网站。
- 共用 DOM 分段也用于单节点翻译，需要回归。字幕、划词弹窗、输入框翻译没有直接修改，安排基础冒烟即可。

## 环境与前置条件

- Chrome 为主测浏览器，Edge 覆盖全部 P0；发布渠道包含 Firefox 时，补充 Firefox 的 P0 冒烟。
- 使用本次提交构建的扩展；解压安装后重新加载扩展，并刷新测试网页。
- 第一轮使用默认设置、目标语言为中文、双语模式。测试源文本必须与目标语言不同。
- THAITICKETMAJOR 使用测试账号登录自己的票务页面，不将账号、密码或个人订单信息写入测试记录。
- 首次加载与缓存命中各测一次。用未翻译过的内容或新页面验证首次请求；命中缓存时译文可能直接出现，不强制要求看到 loading。
- 验证 loading 时，对翻译请求模拟慢响应；验证异常时模拟超时或失败。测试延迟不属于产品行为。
