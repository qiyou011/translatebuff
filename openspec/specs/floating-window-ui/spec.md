# 悬浮窗界面规范

## Purpose

规范悬浮窗的设计一致性与既有交互边界，确保展示调整保留翻译、设置和配置持久化能力。

## Requirements

### Requirement: 悬浮窗展示遵循指定设计

系统 SHALL 按 figma.md 指定节点更新悬浮窗展示，使用经核验的 Figma 资源和属性，不改变已有业务逻辑。

#### Scenario: 展开悬浮窗

- **WHEN** 用户悬停展开悬浮窗
- **THEN** 主入口、翻译、设置、关闭和锁定控件符合指定设计并保持可操作

### Requirement: 悬浮窗不展示反馈入口

系统 SHALL 不在悬浮窗中展示反馈入口，且不修改其他页面共享反馈能力。

#### Scenario: 查看悬浮窗所有入口

- **WHEN** 用户展开悬浮窗并查看入口
- **THEN** 不存在反馈按钮或反馈链接

### Requirement: 既有交互与持久化不变

系统 SHALL 保留悬浮窗的点击配置分支、翻译、设置、展开收起、拖拽贴边、锁定、关闭菜单、键盘触发、全屏处理和 Firefox 侧栏兜底。

#### Scenario: 点击主入口

- **WHEN** 用户以鼠标或键盘触发主入口
- **THEN** 仍按现有 clickAction 配置执行翻译或侧栏动作，Firefox 需用户手势时仍显示既有提示

#### Scenario: 拖动和锁定

- **WHEN** 用户拖动未锁定悬浮窗后释放，或切换锁定并重新加载
- **THEN** 位置与贴边、锁定配置按既有规则保存，释放无新增跳位，锁定与拖拽关系保持既有行为，不增加限制

#### Scenario: 展开与关闭菜单

- **WHEN** 用户悬停、移出或打开关闭菜单
- **THEN** 展开收起规则不变，菜单打开期间保持展开，站点或全局禁用仍写入原有配置

#### Scenario: 翻译设置及全屏

- **WHEN** 用户触发翻译或设置，或拖拽期间进入全屏
- **THEN** 翻译和设置消息及参数不变，全屏仍清理拖拽与鼠标抓取状态
