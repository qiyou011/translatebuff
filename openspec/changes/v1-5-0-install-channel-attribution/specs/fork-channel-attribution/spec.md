## MODIFIED Requirements

### Requirement: UserAgent 携带当前渠道号

系统必须（MUST）令 7 段自定义 `Useragent` 的第 4 段取自安装时固定的渠道号，而非始终直接读取包内号。国内线及没有安装推广记录的海外包仍使用包内解析结果。各段必须（MUST）不含 `/`，保证后端按 `/` 切分恒得 7 段。所有会员与 report 请求必须（MUST）等统一渠道决策完成后使用同一结果。

#### Scenario: [API层] 默认构建 UA 段4 为 7100

- **当** 国内线构建期未注入渠道 id，且系统装配鉴权请求头
- **则** 按 `/` 切分必须恰得 7 段，第 4 段必须为 `7100`

#### Scenario: [API层] 指定渠道构建 UA 段4 为该渠道号

- **当** 国内线构建期注入 `WXT_FORK_CHANNEL=chrome-store`（号码 `7101`），系统装配鉴权请求头
- **则** UA 第 4 段必须为 `7101`，不得恒为 `7100`

#### Scenario: [API层] 海外有效推广覆盖包内号

- **当** 包内号为 `7151` 的海外插件已在新安装时固定选定 `7154`
- **则** 后续所有会员与 report 请求的 `Useragent` 第 4 段必须为 `7154`，且仍恒有 7 段

#### Scenario: [API层] 首次决策尚未完成

- **当** 海外新安装正在异步读取安装前推广记录
- **则** 会员与 report 请求必须等待该次统一决策，不得抢先以暂定包内号发送

### Requirement: 官网跳转链接携带 cid 归因参数

系统必须（MUST）在扩展跳转官网的归因相关链接上追加 `?cid=<渠道号>` 查询参数，取值必须（MUST）与本次扩展自定义 `Useragent` 第 4 段同源：海外线取安装固定号，国内线沿用包内号。覆盖范围必须（MUST）包含登录跳转、订单/支付跳转、卸载问卷跳转三处出站官网链接。追加必须（MUST）稳健处理已有 query / fragment；回跳 `cid` 不代表新的官网推广记录。

#### Scenario: [UI层] 登录跳转追加 cid

- **当** 国内线当前构建渠道号解析为 `7100`，用户在扩展内触发登录
- **则** 打开的官网 URL 必须含 `cid=7100`，且其值等于扩展 UA 第 4 段

#### Scenario: [UI层] 订单跳转追加 cid

- **当** 国内线当前构建渠道号解析为 `7100`，用户在扩展内触发订单跳转
- **则** 打开的官网订单/支付 URL 必须含 `cid=7100`，供官网按渠道归因转化/支付

#### Scenario: [UI层] 卸载问卷跳转追加 cid

- **当** 国内线扩展设置卸载后跳转的官网问卷 URL，当前构建渠道号解析为 `7100`
- **则** 该 URL 必须含 `cid=7100`

#### Scenario: [API层] 目标 URL 已含 query 时正确合并

- **当** 目标官网 URL 已有 `?lang=zh` 等查询参数，扩展追加渠道号
- **则** 必须合并为 `?lang=zh&cid=<号码>`，不得产生第二个 `?` 或覆盖既有参数；fragment 必须保留

#### Scenario: [UI层] 海外回跳使用安装固定号

- **当** 海外 Chrome 商店包内号为 `7151`，新安装已固定选择 `7154`，用户打开登录或订单页，或插件设置卸载问卷 URL
- **则** 三处官网链接的 `cid` 必须为 `7154`，与扩展 UA 第 4 段一致；官网不得因此创建安装推广记录

## ADDED Requirements

### Requirement: UserAgent 携带插件发布版本

国内及海外插件必须（MUST）令 7 段自定义 `Useragent` 的第 6 段取自 `src/fork/identity/fork-version.json`，并通过 `readForkVersion()` 与 manifest `version`、启动事件 `client_version` 共用发布版本来源。会员与登录、匿名 report 请求必须（MUST）使用同一版本，不得硬编码旧版本或使用上游 `package.json` 版本。本次发布配置必须（MUST）为 `1.5.0`；后续发版随该配置更新。

#### Scenario: [构建层] 1.5.0 发布版本一致

- **当** 发布配置的 `version` 为 `1.5.0`，重新构建插件并装配会员或 report 请求头
- **则** manifest `version`、启动事件 `client_version` 和 `Useragent` 第 6 段必须均为 `1.5.0`，UA 仍恰为 7 段

#### Scenario: [API层] 登录与匿名埋点版本一致

- **当** 同一构建分别发送已登录和匿名 report 请求
- **则** 两者的 `Useragent` 第 6 段必须等于发布配置版本，与会员请求一致

#### Scenario: [构建层] 分支名不替代发布配置

- **当** 分支名为 `feat/1.5.0`，但发布配置仍为其他版本
- **则** manifest 和请求 UA 必须使用发布配置版本，发布前必须更新配置并重新构建，不能根据分支名推断版本
