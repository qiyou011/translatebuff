## ADDED Requirements

### Requirement: 海外插件仅在新安装时选择渠道

海外插件必须（MUST）在 `runtime.onInstalled` 的 `install` 事件中、任何异步读取之前捕获本次安装时间。若同一浏览器配置、当前环境官网域下存在已认可的推广记录，且其时间严格早于安装、距安装不足 30 天，插件必须采用推广号；否则必须采用实际包内号 `7150`、`7151`、`7152` 或 `7153`。本期认可推广号仅为 `7154`。选择必须仅发生一次。

#### Scenario: 推广早于安装

- **当** Chrome 商店包内号为 `7151`，同环境官网已成功记录 `7154`，记录早于安装且相距不足 30 天
- **则** 本次新安装必须选定 `7154`，并保留包内原生号 `7151`

#### Scenario: 安装早于推广

- **当** 推广记录在安装事件之后、插件异步初始化完成之前才写入
- **则** 本次安装必须选定包内号，不得把安装后的推广误作安装前来源

#### Scenario: 时间边界与无效证据

- **当** 记录时间与安装时间相等、恰满 30 天、缺失或不可靠，或号码虽为 `71xx` 但未经认可
- **则** 本次安装必须选定包内号

#### Scenario: 不同环境或配置

- **当** 推广记录位于别的浏览器配置、设备、容器，或测试环境与生产环境的另一个官网域
- **则** 插件不得跨环境获取或继承该记录，必须采用当前包内号

### Requirement: 安装选择固定并对失败稳定兜底

插件必须（MUST）保存安装时间与固定选择，后续登录、重启、更新、推广记录覆盖或过期均不得重新计算。旧版插件升级且没有固定结果时必须使用包内号，不得补认历史推广。卸载重装按新的 `install` 事件重新选择，但不得据此推断新增真实用户。

#### Scenario: 已固定后官网推广变化

- **当** 已选定 `7154` 的插件随后遇到新的推广、记录过期或记录被清除
- **则** 插件必须继续使用 `7154`

#### Scenario: 存量升级

- **当** 旧版插件以 `update` 原因升级，且扩展存储没有固定结果
- **则** 插件必须采用包内号，不得读取官网推广记录作补归因

#### Scenario: 首次保存失败

- **当** 新安装已作出选择但固定结果暂时写入失败
- **则** 本次运行必须保留同一选择并尝试补存；进程退出后结果确实丢失时必须回落包内号，不得再消费后来推广

#### Scenario: 读取与权限失败

- **当** 官网 cookie 不可读、用户拒绝所需权限或同意、扩展存储读取失败或超时
- **则** 插件必须稳定回落包内号，不得把未知旧值当新装重新选择，也不得阻断正常翻译

### Requirement: 首批请求等待同一渠道决策

海外插件后台必须（MUST）先建立统一的安装渠道决策，再启动可能发送请求的模块；所有首发会员请求、现有 report 上报和官网跳转都必须等待同一已完成的决策。普通冷启动未收到 `install` 事件时，也必须从已固定结果或包内号完成决策，不能无限等待。

#### Scenario: 新安装并发首发

- **当** 安装事件、匿名启动上报和会员同步几乎同时发生
- **则** 三条通路必须使用同一个已选渠道号，不得在推广选择未完成前抢先发送暂定包内号

#### Scenario: 普通冷启动

- **当** 浏览器重启且没有新的 `install` 事件
- **则** 插件必须从已固定结果或包内号完成决策并继续请求，不得一直等待安装事件

### Requirement: 沿用现有 report 并保留包内来源

海外插件必须（MUST）继续使用现有 `POST /api/data_report/v1/client/click_event` 及原事件触发、去重规则。启动事件的 `action_extra_info.launch_channel_id` 必须为安装固定号；启动与活跃事件的 `action_extra_info.origin_cid` 必须为实际包内号，均为整数。report 请求自定义 `Useragent` 第 4 段必须为安装固定号，时间戳不得作为新增上报字段。安装上报与 `origin_cid` 不得覆盖后端既有注册归因。

#### Scenario: 先推广后安装

- **当** 用户先记录 `7154` 再安装包内号 `7151` 的插件
- **则** 现有启动事件必须以 `launch_channel_id=7154`、`origin_cid=7151` 上报，且同请求 `Useragent` 第 4 段为 `7154`

#### Scenario: 先安装后推广

- **当** 用户先安装包内号 `7151` 的插件，后来官网才记录 `7154`
- **则** 启动与活跃事件中的包内来源仍为 `7151`，插件请求渠道仍为 `7151`，不得重新归因
