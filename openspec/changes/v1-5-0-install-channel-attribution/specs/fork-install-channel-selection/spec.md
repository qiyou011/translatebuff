## ADDED Requirements

### Requirement: 当前官网 Cookie 优先于包内渠道

国内及海外插件必须（MUST）在请求渠道读取时查询同一浏览器配置、当前环境官网域的 `aitrans_cid`。存在可用非空值时必须采用 Cookie 渠道，无可用值时必须直接采用实际包内渠道。系统必须不限制渠道为 `71xx` 或 `7154`；含 `/`、空白或控制字符的值必须视为不可用，以保持 UA 协议。

#### Scenario: 官网 Cookie 覆盖海外 Edge 包

- **当** 包内号为 `7152`，当前环境官网 Cookie 为 `aitrans_cid=9899`
- **则** 请求渠道必须为 `9899`，无需推广记录或安装事件

#### Scenario: 国内也采用 Cookie

- **当** 国内包内号为 `7102`，当前环境官网 Cookie 为 `aitrans_cid=9899`
- **则** 请求渠道必须为 `9899`

#### Scenario: Cookie 缺失、空值或不可用

- **当** 当前官网 Cookie 缺失、为空或无法用于 UA 单独一段
- **则** 插件必须直接使用包内号，不得继承旧安装快照

#### Scenario: 当前环境隔离

- **当** 插件配置官网为测试域，渠道 Cookie 只存在于生产域或其他浏览器配置
- **则** 插件必须只查询当前配置官网，不得跨环境或配置取值

### Requirement: 后续请求跟随 Cookie 变化

插件必须（MUST）每次重新读取当前 Cookie，不固定渠道、不缓存安装选择、不查询 `aitrans_install_promo` 或消费 `fork_install_channel_v1`。新装、冷启动及升级必须遵循同一优先级。读取失败或 1500 毫秒超时必须回落包内号，后续请求必须重新尝试读取。

#### Scenario: Cookie 更新与清除

- **当** 当前 Cookie 从 `9899` 改为 `66666`，随后被清除
- **则** 后续请求必须依次使用 `9899`、`66666`、包内号

#### Scenario: 已安装插件升级

- **当** 扩展存储存在旧固定 `7154`，当前 Cookie 为 `9899` 或不存在
- **则** 请求必须分别采用 `9899` 或包内号，旧记录不得影响选择

#### Scenario: 读取失败后恢复

- **当** Cookie 读取异常或超时，下一次请求时读取恢复且值为 `9899`
- **则** 当前失败请求必须使用包内号，下一次必须使用 `9899`

### Requirement: 请求等待本次渠道读取

国内及海外插件必须（MUST）在会员与 report 请求发送前完成本次渠道读取或失败兜底。后台必须先注册页面渠道消息，再启动网络模块。单次启动上报必须（MUST）只读取一次渠道并同时用于请求体和 UA。

#### Scenario: 首发请求等待 Cookie

- **当** report 正在等待异步读取 `aitrans_cid`
- **则** 请求必须在读取完成或超时兜底后发送，不得抢先使用暂定包内号

#### Scenario: 同一次启动上报期间 Cookie 变化

- **当** 启动事件已读取渠道 `9899`，随后 Cookie 改为 `66666`
- **则** 该次启动上报的 `launch_channel_id` 和 UA 第 4 段必须都为 `9899`，下一次请求再使用新值

### Requirement: 沿用现有 report 并保留包内来源

海外插件必须（MUST）继续使用现有 `POST /api/data_report/v1/client/click_event` 及事件触发、去重规则。启动 `launch_channel_id` 必须为本次请求渠道；启动和活跃 `origin_cid` 必须为实际包内整数号。系统必须不以请求渠道覆盖后端既有账号注册归因。

#### Scenario: Cookie 改变但包内来源不变

- **当** 海外包内号为 `7151`，Cookie 从 `9899` 改为 `66666`
- **则** 后续启动 `launch_channel_id` 和请求 UA 必须随 Cookie 改变，`origin_cid` 必须一直为 `7151`
