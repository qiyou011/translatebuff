## Decisions

### D1：固定正式目标完整同步

用 `git merge --no-ff --no-commit 55bcef1e684fb4e70f4dce3063e7bd3066f46891` 保留待完成的合并关系；先隔离自动发布/通知，合并后再次复核。冲突按业务行为解决，不批量 take-theirs。锁文件通过目标 pnpm 重新生成。合并提交仅表示来源关系；`lastSyncedSha/version` 必须等最终 G1—G7 被接纳再推进。

### D2：公共逻辑与自有边界

上游拥有通用翻译引擎、schema 100→111 及迁移、消息、公共状态和交互；fork 拥有品牌视图/外壳、自有服务与准入。选择公开 Provider/hook/状态加薄包装，而不是长期搬运完整控制器；没有公开接口的输入编排和 Toolbar 仍保留必要最小副本并对账，不新建通用扩展框架。品牌效果和已有业务回归是冲突选择依据。

具体接线：标题使用 `translateTitle`、现有 manager 配置监听及上游迁移；iframe 使用上游 trigger、后台消息、可信手势与两级站点控制，fork Toolbar 补 ready/延迟事件/清理；Reddit 使用公开 Lexical adapter 与深层焦点方法，fork hook 保留三连空格、Telegram/Discord、撤销与迟响应保护；App 挂载上游 `SelectionSpeechProvider`，避免共享按钮缺 context；翻译中心共享状态/设置包装并保留自有服务和品牌卡片。

### D3：最小产品准入与四层商业隔离

新增 `src/fork/upstream-admission.ts`，以只读明确常量和批准内置动作 ID 集合表达本轮许可；默认保留已有词典、自定义动作与业务效果。有效可用性为产品准入、用户设置和已有服务条件的交集。目标迁移写 enabled=true 也不得越过准入；不通过不断改 false 覆盖用户设置。

所有未批准功能及商业能力须检查入口/直接路由、挂载/初始化副作用、后台消息/任务、请求前四层。继续使用本地禁用 RPC transport、空认证会话、后台停用与 provider 解析。保留导出/消息兼容，禁用明确完成或拒绝，不假成功、不自动重试、轮询和持续 loading；不以全局域名黑名单误伤用户 provider，不将未批准功能自动转自有收费请求。平台准入在实际注入/执行前控制，X/Netflix 与学习侧栏源码虽保留但不运行。

### D4：动作时读取输入上下文

上游 `readSelectionSnapshot` 会读取完整 value，fork mouseup 会调用它，因此必须拆分选区显示快照和动作上下文捕获：展示阶段只保留选中文本、范围及必要控件引用，不提前读取完整 value；显式翻译/AI动作触发时才从仍连接的同一控件取当前值及选区相关段落，并检查类型和敏感属性。允许 text/search 和 textarea，排除 email/tel/password/url 及可识别验证码、支付等敏感字段；取消、只展示、自动笔记建议不采集控件上下文。不后台采集、不新增上送字段，长页上下文保持原字段及 2000 字符上限。

### D5：术语库贯通自有队列

复用上游 IndexedDB repository、CSV、matcher、快照和 prompt builder。`src/fork/page-translation/types.ts` 的页面请求、`queues.ts` 合批 key、`llm.ts` prompt、MT/LLM分流和 `index.ts` 单条降级均传递匹配 terms 与 revision；缓存身份包含实际生效的术语状态，revision 不同不得合批，同批 terms 按已匹配项目去重并处理不一致快照。修改/删除后不得命中旧措辞；重试和单条降级使用同一有效术语身份。Google/Microsoft 纯 MT 保持正常路径，不宣称强制术语。当前 JSON/MT 批处理及交互队列隔离先保留。

实施审查补充：全局 revision 不能独自代表有效术语状态，同源 SPA 不同路径可在同一 revision 匹配不同词条。合批 key 同时包含稳定排序的实际匹配 terms；相同集合可继续合批，空词条保持原策略。不同匹配集合分别请求，避免把合并后失去约束的结果写入各自缓存；这可能增加启用术语时的请求批次。该取舍只收紧正确性分组，不调整批量大小、并发或超时，不新增另一份 scope/schema/消息模型。

降本兼容复核：内容缓存仅对非空有效术语集合追加 revision；空集合保持无术语内容缓存身份，避免默认空库或不相关编辑造成重新请求。删除至空时允许复用添加术语前的等价无术语缓存，但不得复用带已删除约束的结果。请求仍携带真实快照，队列按 revision 与有效集合分组的保护保持不变。独立架构复审记录见 `evidence/cost-reduction-preservation/cache-scope-arch-review.md`。

## 数据模型与接口契约

- 上游配置迁移链保持单一权威来源；新增术语数据使用上游Dexie schema；不另存品牌同义配置。
- `src/fork/upstream-admission.ts` 导出不可变准入配置与 `isApprovedBuiltInAction(id: string): boolean`；调用方在入口和实际执行前消费，文档不参与运行。
- 页面术语类型复用上游 `MatchedTerm`、revision/快照字段，不建立第二份词条模型；合批请求、缓存与fallback必须表达同一有效快照。
- 输入显示快照与显式动作捕获分离；控件类型/敏感属性/连接状态在捕获时重查。
- 禁用路径继续使用既有可识别且不可重试的错误语义；原状态消息返回契约规定的null，绝不发起被禁用请求。

## Risks / Trade-offs

大范围合并与依赖升级容易把“编译通过”误认为真实集成完成；先记录基线测试，再运行原套件和fork配置套件。首轮保留必要副本增加临时对账成本，优先无额外抽象的公开接口复用。大量旧上游/UI测试可能不执行fork重定向，必须显式覆盖实际路径。Firefox最低版本140和目标Node/pnpm等工具链作为产物条件记录。

G1来源/完整合并/无未解决图风险，G2测试类型格式边界品牌构建，G3实际fork与自有业务，G4品牌与准入，G5实包SW/扩展页/content script零上游商业请求且自有服务正常，G6schema升级/数据备份恢复及旧版回退，G7发布隔离及最终SHA/包证据。任何必需项失败或缺覆盖不得标记维护基线已推进。

回退：原业务分支和4be99代码保持；保存升级前配置及术语数据备份、当前候选配置版本和产物hash。旧版若拒绝升级后配置，必须先验证恢复旧备份再换包；不能只回滚代码。当前不做真实发布。
