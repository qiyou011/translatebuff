## MODIFIED Requirements

### Requirement: 三类上游云服务统一禁用

系统 SHALL 在国内、海外的开发、测试、正式构建中，阻止上游功能链路对 `/api/identity`、`/api/rpc`、`/api/blog` 前缀本身及其子路径发起网络请求，并 MUST 将固定目标新增的上游账号、购买、订阅、计费及独家云能力纳入同一隔离边界。禁用不得依赖上游域名或用户手动开关，也不得改写自有环境变量为无效地址。系统 MUST 不以浏览器全局路径或用户自配 domain 黑名单替代功能边界隔离。

#### Scenario: 不同发行版与环境采用相同策略

- **WHEN** 任一发行版和环境启动扩展并使用上游账号、购买订阅、云服务或博客相关代码路径
- **THEN** 上游商业及独家云服务均在本地结束，真实 fetch 和 backgroundFetch 出口均无对应网络请求，不因新增客户端或端点更名绕过隔离

#### Scenario: 不误伤用户指定的外部服务

- **WHEN** 普通网页或用户自配 provider 使用与被禁用端点相同的路径名称，或配置了与上游服务相同的 domain
- **THEN** 系统按调用所属的功能与 provider 契约处理，不按浏览器全局路径或粗粒度 domain 黑名单阻断正常请求，不改写该用户配置

### Requirement: 云功能界面与后台触发停止

系统 SHALL 在入口与路由、初始化副作用、后台任务与消息、请求前四层隔离上游商业及独家云能力；隐藏上游账号、购买订阅、托管 AI 配额、云转录、Notebase 云保存及博客通知入口，停止相关查询、初始化和后台业务触发，并保留已有调用需要的消息及模块导出契约。仅隐藏界面 MUST 不被视为隔离完成。

#### Scenario: 扩展页面不启动云查询

- **WHEN** 用户打开弹窗、设置页、划词界面、直接访问相关路由或恢复旧页面状态
- **THEN** 不显示或推荐不可用云功能，不挂载查询、不初始化专属 SDK 或启动副作用，不出现持续 loading 或上游登录、购买和订阅诱导

#### Scenario: 后台重启与会话变化

- **WHEN** 扩展冷启动、Service Worker 重启或认证 Cookie 变化，且存在旧 Notebase 待保存任务
- **THEN** 不运行云笔记保存任务、不请求上游身份或 RPC，且不删除待保存数据；新目标引入的后台初始化、定时任务或消息触发同样不能绕过禁用

#### Scenario: 托管 AI 状态消息保持可响应

- **WHEN** 调用方发送 getHostedAiStatus 消息，或代理层调用状态缓存清理导出
- **THEN** 调用正常完成；状态消息返回 null，不读取旧可用状态、不请求服务器、不发生处理器或导出缺失错误

#### Scenario: 直接触发禁用能力的消息或请求

- **WHEN** 旧配置、直接路由或调用方绕过界面触发禁用能力
- **THEN** 后台消息和请求前边界仍在本地结束调用，不因入口不可见而放行，不使调用方等待永不结束的响应

### Requirement: 意外云调用明确终止

系统 SHALL 对仍然触达的上游 RPC 和不支持的认证、购买及订阅操作快速返回可识别的禁用结果，不模拟业务成功、不回退到原上游客户端，且不得因该结果自动重复调用、轮询或持续显示加载状态。博客查询 SHALL 按既有契约返回 null。禁用 MUST 不自动转为其他未经批准的收费请求。

#### Scenario: 绕过运行时兼容直接触发普通或流式 RPC

- **WHEN** 调用绕过请求前兼容边界进入任一上游 RPC 客户端，包括流式请求
- **THEN** 请求在本地被拒绝，调用流程结束，不联网、不伪造译文或云保存成功、不自动重试或回退到上游；请求前解析到合格 local provider 的既有正常兼容调用不属于该禁用失败路径

#### Scenario: 禁用与正常任务并存

- **WHEN** 同一队列存在禁用调用与使用有效非上游 provider 的正常翻译
- **THEN** 禁用使用独立错误语义及既有不可重试标记，不借用账号、额度或 access-denied/401/403/404 错误触发共享队列失败；正常任务不被连带终止，禁用流程不持续加载

#### Scenario: 流式端口只保留错误文本

- **WHEN** 前端准备执行禁用模型请求，且后续端口不保留结构化错误元数据
- **THEN** 前端在请求前结束禁用路径，不依赖端口传回不可重试标记才能终止，不修改全局重试规则或消息协议

#### Scenario: 博客直接调用或旧缓存存在

- **WHEN** 代码直接调用 getLatestBlogDate，或者用户打开含旧博客缓存的界面
- **THEN** 查询返回 null 且不联网，界面不因旧缓存重新显示更新提示，其他纯工具功能保持不变

### Requirement: 上游翻译核心与自有业务保留

系统 SHALL 保留上游翻译核心、当前支持的非上游 provider 路径，以及任译喵登录、会员权限、额度、模型网关、渠道归因、Telegram 与 Discord 输入增强、自定义动作和既有批处理策略。系统 MUST 保留当前发行版品牌、UI 主题、图标和布局；隔离上游云能力不得改变自有路径的域名、请求协议或独立状态，不以本变更扩大当前隐藏模型的 UI 支持范围。

#### Scenario: 自有登录与模型服务继续运行

- **WHEN** 用户恢复任译喵会话、查询会员权限或额度、发起网关翻译、打开官网或执行登出
- **THEN** 行为与改造前一致，沿用自有服务和凭据规则；上游无会话状态不清除自有凭据、不改变自有接口地址，不把本地 key 非空视为服务端权益证明

#### Scenario: 翻译功能回归

- **WHEN** 用户使用自配 provider、页面翻译、划词翻译、普通字幕提取及翻译，或 Telegram、Discord 输入翻译
- **THEN** 不依赖上游云服务的路径继续工作；既有三空格触发、修改译文后撤销回原文、失焦再聚焦和语言菜单搜索行为保持不变，原批处理、请求有效性及队列降级契约保留

#### Scenario: 字幕高级处理与云转录区分

- **WHEN** 用户提取并翻译已有字幕，或使用既有已批准的字幕摘要与分段能力
- **THEN** 前者继续运行，后者依照所选模型的 LLM 能力执行；不要求纯翻译器生成摘要，不因上游云转录禁用而关闭普通字幕功能，不自动启用新目标未批准的 sidebar 或云转录

#### Scenario: 自定义动作与笔记功能区分

- **WHEN** 用户使用已有自定义动作或内置词典，或打开当前 fork 划词界面
- **THEN** 合格非上游模型的生成能力保留，Notebase 云保存不可用；当前已移除的笔记建议入口与生成调用不得因兼容逻辑而恢复，新增内置动作 ID 另按准入规则处理

#### Scenario: 品牌与渠道不因完整同步回退

- **WHEN** 国内或海外用户打开主要界面、安装或升级后触发渠道归因
- **THEN** 国内任译喵和海外 TranslateBuff 品牌、现有主题图标布局及渠道行为保持；复用上游通用能力不恢复上游品牌 UI 或混用自有渠道状态

### Requirement: 旧上游模型在运行时兼容且不新增配置迁移

系统 SHALL 在页面、划词、输入、字幕翻译及已有自定义动作构造请求前，将旧 system provider 引用临时解析到现有配置中首个启用、能力匹配且满足现有凭据门控条件的任译喵 provider；有效 local 解析结果 MUST 保持不变。无合格候选 SHALL 在业务请求前结束并引导登录或选择模型，不新建 provider、不请求上游、不自动重试、不回退到任意其他收费服务。运行时兼容本身 MUST 不新增持久化配置迁移；本轮正式目标的 schema 100→111 仍复用上游迁移链。语言检测、当前关闭的笔记建议及本轮未批准功能 MUST 排除在此自动替代规则外。

#### Scenario: 不依赖打开设置完成旧配置兼容

- **WHEN** 扩展冷启动或恢复旧配置，用户未打开弹窗、设置或重新登录，翻译配置引用 system 且已有合格候选
- **THEN** 按配置顺序解析为真实 local provider 再构造请求，使用既有服务和额度规则；兼容不依赖 UI 挂载或新增持久化迁移

#### Scenario: 显式旧快照与无合格候选

- **WHEN** 调用方直接传入 system 快照绕过常规解析，或现有候选缺 key、被禁用、不支持该能力
- **THEN** 显式快照仍按同一规则在请求前处理；没有合格候选时给出可操作提示，不查询 hosted 状态、不进入生成或重试，不伪装为翻译成功

#### Scenario: 实际执行模型与参数缓存一致

- **WHEN** 持久化选择仍为上游模型，但本次已解析为任译喵 local provider
- **THEN** 提示词、模型参数、温度、术语 revision、缓存标识、统计和执行模型展示使用最终 local provider 及本次请求上下文，不复用旧 hosted 身份缓存，不为修正展示写回持久化选择

#### Scenario: 不改变现有配置和会员同步职责

- **WHEN** 运行时做兼容决策，或既有种子、登录及凭据同步流程正常执行
- **THEN** 兼容逻辑不新增配置写入或批量重指向，既有同步行为保持不变；同步解析器不读 storage、不做网络或会员刷新、SDK 初始化，必要的异步流程仍在原边界执行

#### Scenario: 候选凭据不等于服务端权益确认

- **WHEN** 候选满足本地 key 条件，但凭据已过期或实际额度不足
- **THEN** 使用现有凭据、权限和额度处理，不将 key 非空当成有效会员证明，不新增权益判断体系或更换付费服务；有效非上游模型配置不被新兼容逻辑替换

### Requirement: 改动与上游同步边界可控

系统 SHALL 复用固定正式目标的公开 Provider、hook、状态、消息、翻译引擎和配置 schema，新增 fork 适配代码置于 `src/fork`，沿用既有模块重定向与指纹守卫；MUST 以薄包装为默认，必要副本逐项对账，不新增平行框架或第二 schema。完整同步 SHALL 接纳目标内获准的上游通用变化和既有 100→111 迁移链，但 MUST 保留 fork 的 UI 与业务契约，不借同步扩大通用 allowlist 或用批量指纹更新掩盖漂移。

#### Scenario: 同步到被覆盖模块的改动

- **WHEN** 合并上游后被重定向文件移动、缺失或内容改变
- **THEN** 既有构建守卫阻止静默继续，维护者先检查上游贡献、实际 fork 路径与适配方式，再更新注册和指纹，不以批量刷新绕过检查

#### Scenario: 上游新调用路径引入

- **WHEN** 上游新增 RPC 方法、客户端、后台消息、初始化任务或直接网络调用
- **THEN** 共用禁用出口的方法继续被拒绝，并逐项审查新路径的入口、初始化、后台及请求前四层边界；不能以无 Git 冲突、类型检查通过或旧出口已禁用代替运行时验收

#### Scenario: 薄包装保持依赖与内部调用边界

- **WHEN** 冷启动导入 provider 或语言适配模块并调用其公开入口
- **THEN** 候选规则仅依赖纯身份叶子、原能力判断和类型，不通过配置或任译喵大模块产生新循环；需要协作的函数显式调用 fork 实现，不被上游模块内部词法调用绕过，原模型分类和配置同步算法保持不变

#### Scenario: 需要保留上游 App 副本

- **WHEN** 现有 UI 和业务契约无法仅靠公开入口薄包装保留，需要继续维护 App 或组件副本
- **THEN** 记录副本与固定目标的差异、需吸收的上游行为及保留原因，纳入来源和执行路径回归；未登记副本不能因不在重定向表中而免于审查

### Requirement: 隔离验收覆盖真实运行路径

系统 SHALL 同时提供加载 fork 重定向的契约与 UI 测试及真实构建包网络验证，并保留原上游测试。验收记录 MUST 区分代码测试、构建与浏览器实证，绑定冻结候选 SHA、发行版、构建环境及实际加载产物；未具备账号或模型条件的项目 MUST 明确待验收，不能判定通过。

#### Scenario: 双发行版构建和浏览器验证

- **WHEN** 准备验收本轮完整同步的云隔离和自有服务
- **THEN** 国内 Chrome、Edge、Firefox 三浏览器包与海外代表包通过所需构建门；真实包回归页面、划词、输入、字幕、语言检测、自定义动作、本地术语及自有登录，记录实际浏览器与产物，不能以构建成功代替功能验证

#### Scenario: 三执行上下文零上游商业请求

- **WHEN** 在 Service Worker、扩展页面和 content script 中执行冷启动、后台重启、旧配置恢复及相关交互
- **THEN** 三个上下文均记录上游商业与独家云请求为零，并有自有服务及合格自配 provider 正常工作的对照；直接路由、消息或新调用出口不绕过四层边界，缺少任一上下文证据不算隔离验收通过

#### Scenario: 外部测试明确跳过

- **WHEN** 本地测试设置 `SKIP_FREE_API=true`
- **THEN** `free-api.test.ts` 被明确记录为有意跳过，不被计作外部在线翻译服务验证通过，也不补足缺失的实包网络证据

## ADDED Requirements

### Requirement: 新增功能与动作 ID 按批准清单启用

系统 SHALL 将完整 merge 的源码与对外功能准入分开，只启用已批准的能力；未审查的 X、Netflix、sidebar 及新增内置动作 MUST 保持关闭，其路由、初始化、后台和请求前触发同样受控。系统 MUST 保留已有词典与用户自定义动作，不以名称相似或共用生成引擎将未批准功能自动映射到自有收费请求。

#### Scenario: 上游迁移或默认配置引入新内置动作 ID

- **WHEN** 新配置或 100→111 迁移带入此前未批准的内置动作
- **THEN** 依据稳定动作 ID 执行准入，未批准项不显示、不初始化、不生成请求；已有词典和用户自定义动作不因该清单被整体禁用或删除

#### Scenario: 未批准功能引用旧 system provider

- **WHEN** 未批准的 X、Netflix、sidebar、新内置动作或云能力带着旧 system provider 引用被直接触发
- **THEN** 先按功能准入在本地明确结束，不进入已有运行时 provider 替代流程，不产生自有或其他收费模型请求，不重试、不持续 loading

#### Scenario: 本地术语与 Drive 同步区分

- **WHEN** 用户使用已批准的本地术语管理、CSV 或自有 LLM 术语注入
- **THEN** 本地能力正常运行，Drive 的入口、授权、初始化及自动同步保持关闭，普通配置备份恢复继续按既有本地契约工作
