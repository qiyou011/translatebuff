## ADDED Requirements

### Requirement: 本轮功能准入范围可追溯

系统 SHALL 将固定正式版 `v1.51.0 / 55bcef1e684fb4e70f4dce3063e7bd3066f46891` 内已批准的 15 项产品修复作为本轮重点保留与回归范围，并 MUST 将功能行为、实际 fork 执行路径和验收证据逐项对应。完整 merge 包含上游源码不等于新增功能全部获准启用。

#### Scenario: 原产品清单含正式版之后的修复

- **WHEN** 对照原 16 项产品清单与固定目标提交
- **THEN** 仅纳入目标内的 15 项；目标之后的 `1308e8d1` 论文摘要重排修复保持排除，不通过额外 cherry-pick、补丁或漂移目标 SHA 混入本轮

#### Scenario: 上游原件已更新但 fork 仍覆盖执行路径

- **WHEN** 某项修复所在模块被重定向或被 fork 副本间接替代
- **THEN** MUST 在实际 fork 路径验证并适配该修复，不能仅凭上游提交已是合并祖先或原件测试通过判定交付

### Requirement: 零行高脚注中的块级译文不重叠

系统 SHALL 保留来源 `625bb2d8` 的脚注修复：块级译文继承到零行高时 MUST 使用可正常排布多行文本的行高，行内译文 SHALL 保留原有行内排版行为。

#### Scenario: GitHub 脚注译文换行

- **WHEN** 页面脚注位于 `line-height: 0` 的 `sub` 等祖先内，块级译文超过一行
- **THEN** 各行译文具有正常垂直间距和内容高度，不重叠于同一位置；未命中零行高条件的译文不被无条件改写行高

### Requirement: 长页上下文在既有字段和上限内保持响应

系统 SHALL 保留来源 `49f0db1c` 的长页处理，沿用既有网页标题、描述、正文上下文字段及正文 2000 字符上限；MUST 在 Markdown 转换前约束待处理正文并处理深层嵌套表格，避免仅为有限上下文完整转换长页。系统 MUST 不新增第二套页面上下文或因翻译后的标题、同页锚点变化重复失效缓存。

#### Scenario: 长 Wikipedia 页面包含深层嵌套表格

- **WHEN** 已批准的 AI 动作请求读取长页上下文
- **THEN** 返回既有字段且正文不超过 2000 字符，深层嵌套表格不导致长时间阻塞；提取失败沿用既有正文降级行为

#### Scenario: 同页标题翻译或锚点跳转

- **WHEN** 页面原文未变，仅显示译后标签标题或执行同页锚点跳转
- **THEN** 既有上下文使用页面自己的源标题，不因上述展示变化重新解析含译文的页面或清空可复用缓存

### Requirement: 动态包裹不重复翻译既有双语段落

系统 SHALL 保留来源 `f672b31d` 的动态 DOM 去重：站点在已翻译双语段落内部增加临时包裹时，MUST 不将包裹内已有内容再次作为新段落翻译。

#### Scenario: 悬停或动态组件包裹已翻译文本

- **WHEN** 双语译文已完成，站点随后在该原段落中插入临时 wrapper
- **THEN** 同一内容不重复请求、不叠加译文或加载节点，段落外新出现的独立原文仍可正常翻译

### Requirement: React 19 重写仅复用完成且同结构的双语结果

系统 SHALL 保留来源 `eab2f3ca` 的稳定性修复，仅对已完成、原文及相关 DOM 结构相同的双语结果进行复用；MUST 不把纯文本相同视为结构相同，不复用 pending、失败或过期结果。

#### Scenario: React 19 将段落重写为相同结构

- **WHEN** 已完成的双语段落被 React 19 重写且符合上游同结构判定
- **THEN** 复用已完成结果，避免重复请求、闪烁及页面跳动

#### Scenario: 文本相同但结构或请求状态不同

- **WHEN** 站点改变段落中的链接、行内原子等相关结构，或原翻译尚未完成、已失败或失效
- **THEN** MUST 按当前结构与请求生命周期处理，不将旧结果错误挂到新段落

### Requirement: 输入控件上下文仅在显式动作时读取

系统 SHALL 在来源 `3f8a2acf` 的输入上下文能力上施加本轮隐私边界：仅普通 `input[type=text]`、`input[type=search]`、等价的默认 text 输入框及 `textarea` 可在用户显式执行已批准动作时读取当前完整 `value`。系统 MUST 排除 `email`、`tel`、`password` 和依靠既有字段语义可识别的敏感字段；仅展示工具栏、鼠标选择结束或 `mouseup` MUST 不读取完整 `value`。

#### Scenario: 用户对普通输入框选中文本执行动作

- **WHEN** 用户在允许的普通输入框中选中文本并显式执行已批准动作
- **THEN** 才读取当时的完整 `value` 作为该字段上下文；`textarea` 仅向动作提供包含所选文本的相关段落，不误用页面标题、样式表或其他字段内容

#### Scenario: 仅选择文本或显示工具栏

- **WHEN** 用户选择文本、释放鼠标或仅显示工具栏，尚未执行动作
- **THEN** 完整 `value` 的读取次数为零，不提前采集、缓存或发送完整字段值

#### Scenario: 敏感字段与无关页面节点

- **WHEN** 选择位于 email、tel、password 或可识别敏感字段内，或上下文候选来自 `head`、`style`、`script`、`noscript`、`title`
- **THEN** 敏感字段完整值不被读取或发送，上述页面节点不进入动作上下文；排除条件不因直接调用上下文构造入口而被绕过

### Requirement: Google 引用悬浮卡译文可见且保留内部滚动

系统 SHALL 保留来源 `6e7225d7` 对 Google AI Overview 引用悬浮卡的修复，解除导致译文裁切的限制，并 MUST 保留卡片的内部滚动与页面其余容器的原有行为。

#### Scenario: 引用卡译文长于原文

- **WHEN** 用户打开 Google AI Overview 引用悬浮卡并显示长译文
- **THEN** 译文不被原文行数或高度裁切，超出可用空间时仍可在卡片内滚动，不以全站取消滚动或溢出约束实现

### Requirement: Wikipedia 服从全局短文本设置

系统 SHALL 保留来源 `308a08d7` 的 Wikipedia 规则修复，使其短文本过滤服从用户全局配置，不由内置站点规则强制覆盖。

#### Scenario: 调整全局短文本阈值

- **WHEN** 用户改变全局最少字符或最少词数设置后翻译 Wikipedia 标题及短段落
- **THEN** 实际过滤结果遵循该配置，既不固定跳过所有短标题，也不绕过用户的过滤阈值

### Requirement: Kaggle Learn 指南排版与公式保留

系统 SHALL 保留来源 `50842cf2` 的 `.learnGuide` 适配，使 Kaggle Learn 指南中的译文不重叠；MUST 保留指南中的公式节点及其原有渲染，不扩大为全站无差别样式覆盖。

#### Scenario: 指南正文含公式且译文变长

- **WHEN** 用户翻译包含公式的 Kaggle Learn 指南
- **THEN** `.learnGuide` 内译文正常占据排版空间，正文不重叠、公式保持可读；指南外布局不受该局部规则影响

### Requirement: YouTube 原生自动字幕覆盖完整时长

系统 SHALL 保留来源 `b81a4b96` 的原生自动字幕时序处理，依据下一分段偏移或事件声明时长确定 cue 结束时间，MUST 不仅以固定词时长使句子提前消失。

#### Scenario: 自动字幕句子仅含最后一个分段

- **WHEN** YouTube 原生自动字幕事件的最后分段对应整句且声明时长长于估算词时长
- **THEN** 字幕持续显示到该分段应有的事件结束时间，句内分段仍按下一偏移衔接，字幕优化后不丢失该可见时段

### Requirement: 行内代码在两种翻译模式中保持原样

系统 SHALL 保留来源 `26515768` 的 arXiv、ar5iv 行内代码保护，双语及仅译文模式 MUST 保留代码标识符及其必要显示属性，独立代码清单和纯代码段落 MUST 不产生无效翻译请求；两种模式的短文本过滤 SHALL 以可翻译正文为准。

#### Scenario: 自然语言段落含重复代码标识符

- **WHEN** 用户以双语或仅译文模式翻译含多个行内代码节点的论文段落
- **THEN** 自然语言被翻译，每个代码标识符保持原样且不丢失或合并，恢复原文时原代码节点仍可正常显示；代码内容不被计入可翻译正文以绕过短文本阈值

### Requirement: 同源 iframe 工具经可信手势懒激活

系统 SHALL 保留来源 `766b7d33` 的同源 iframe 懒激活，仅在可信用户选择手势后加载完整工具运行时；顶层页与 frame 的站点控制和 iframe 注入规则 MUST 同时允许，划词工具开关及禁用模式 MUST 继续生效。浏览器给出的不透明 sandbox 来源 `null` MUST 被拒绝，不能回退用 URL 冒充同源。

#### Scenario: 首次在允许的同源 iframe 选择文本

- **WHEN** 真实用户在同源 iframe 中选择文本，顶层和 frame 均通过站点及注入规则且划词工具允许
- **THEN** 才请求完整运行时；加载后仅重放仍保持相同节点、偏移和文本的选择，同一 frame 文档不重复注入

#### Scenario: 非可信事件或任一层禁用

- **WHEN** 页面脚本合成选择事件、顶层或 frame 被禁用、划词工具关闭，或 frame 为跨源或不透明 sandbox
- **THEN** 不经懒激活路径加载完整运行时；失败或文档变化不保留过期选择节点，不越过原有显式跨源注入边界

### Requirement: 标题翻译开关复用上游配置并可恢复原题

系统 SHALL 保留来源 `598432ef` 的 `pageTranslation.page.translateTitle`、上游 schema 默认值及迁移；默认 SHALL 为 `true`，已存 `false` MUST 保留。开关仅决定标签页显示，提示词及缓存身份 MUST 使用页面源标题，不引入 fork 的第二标题字段或迁移。

#### Scenario: 旧配置升级后切换标题开关

- **WHEN** 旧配置通过上游迁移获得默认开启的标题开关，随后用户关闭标题翻译
- **THEN** 页面正文翻译继续运行，标签页恢复并保持页面自己的标题；再次开启遵循当前页面翻译状态，已保存的关闭选择不被再次迁移覆盖

#### Scenario: 标题变化与同页跳转

- **WHEN** 仅切换标题显示或跳转同页锚点
- **THEN** 不用译后标题污染上下文或缓存键，不因此重新翻译整页；关闭页面翻译时可恢复应有的源标题

### Requirement: YouTube 字幕拖拽与菜单事件保持局部

系统 SHALL 保留来源 `f347fa5f` 的字幕拖拽、pointer 事件及菜单定位修复；字幕菜单 MUST 约束在视频可用范围并位于播放器自身菜单下方，拖拽和菜单操作 MUST 不误触发播放器点击或快捷行为。

#### Scenario: 拖拽字幕并打开长菜单

- **WHEN** 用户在普通视频或 Shorts 中拖拽字幕位置、结束 pointer 操作并打开字幕菜单
- **THEN** 拖拽状态正常结束，后续操作仍可用；菜单内容在视频可用空间内可访问，不遮盖播放器自身菜单，不向播放器泄漏本应由字幕控件处理的事件

### Requirement: Reddit 输入翻译保留深焦点与撤销语义

系统 SHALL 保留来源 `0bfc7acd` 的 Reddit 回复编辑器适配，兼容 Lexical 和深层焦点，贯通 fork 现有三连空格、语言纠正、失败反馈及不可变原文撤销契约。

#### Scenario: Reddit 回复框触发翻译后编辑并撤销

- **WHEN** 用户在 Reddit 的 Lexical 回复编辑器内连续输入三个空格触发翻译，成功后修改译文并点击撤销
- **THEN** 翻译只写入实际触发的编辑器，撤销恢复触发前含原有首尾空白的原文；深层焦点、输入法和编辑器事件不导致会话串到其他回复框

#### Scenario: 既有聊天增强回归

- **WHEN** 用户在 Telegram 或 Discord 执行既有输入翻译、失焦后恢复或语言菜单操作
- **THEN** 原有请求有效性、发送后清理、原文重译及撤销语义保持成立，不以覆盖 fork 输入编排换取 Reddit 适配

### Requirement: body 替换后保持同一控件根与状态

系统 SHALL 保留来源 `f1cde34a` 的客户端 body 替换处理，在新 body 上重新安置同一 shadow host 并保留其 React 状态；MUST 不为每次替换重建独立控件根。

#### Scenario: 客户端路由替换整个 body

- **WHEN** 站点客户端导航替换 body，而扩展控件已挂载并具有当前交互状态
- **THEN** 同一 shadow host 连接到新 body，控件继续可用且 React 状态保留，不产生重复控件、重复监听或孤立旧 host

### Requirement: 本地术语库沿用上游存储与管理契约

系统 SHALL 开放本地术语库、CSV 导入导出及上游既有站点和语言适用范围，复用上游配置和本地存储契约，并在 fork 品牌界面提供必要入口；Google Drive 同步 MUST 保持关闭，不因术语能力初始化而授权、同步或发起云请求。

#### Scenario: 本地管理与 CSV 往返

- **WHEN** 用户新增、修改、删除术语，或导出后重新导入 CSV
- **THEN** 本地术语及其站点、语言范围按既有规则可用，重新打开设置后仍可读取，不需要上游账号或 Drive 服务

#### Scenario: 术语不适用于当前站点或语言

- **WHEN** 术语的站点或语言范围不匹配本次翻译
- **THEN** 该术语不注入请求，不因存在于本地库中而全局生效

### Requirement: 术语注入贯通自有 LLM 合批与缓存

系统 SHALL 将适用术语注入最终解析的自有 LLM 翻译请求，并贯通 fork 现有页面合批与缓存。单次任务使用的术语内容和 revision MUST 一致，批次、请求及缓存身份 MUST 能区分影响结果的术语 revision；MUST 不新建平行队列、术语 schema 或独立配置迁移。

#### Scenario: 修改或删除术语后再次翻译

- **WHEN** 用户修改或删除适用术语后，以相同文本和自有 LLM 再次翻译
- **THEN** 新任务采用新的术语 revision，不错误命中旧 revision 的译文；同一合批请求不混用互不一致的术语快照

#### Scenario: 运行时 provider 兼容与术语并存

- **WHEN** 旧 system 引用被现有兼容规则解析到合格的自有 LLM
- **THEN** 术语、提示词、模型参数及缓存身份均基于最终执行 provider 和同一术语快照，保留既有会员、额度与合批策略

#### Scenario: 术语读取或注入失败

- **WHEN** 本地术语读取或注入失败，但普通翻译路径可用
- **THEN** 按既有失败降级边界继续普通翻译，不请求 Drive 或上游商业服务，不把失败结果当作包含术语的新 revision 缓存成功结果

#### Scenario: 选择纯机器翻译服务

- **WHEN** 用户使用 Google Translate、Microsoft Translator 等纯机器翻译 provider
- **THEN** 保留该服务原有翻译路径，不承诺术语强制生效，不为实现术语效果自动切换到收费 LLM
