## ADDED Requirements

### Requirement: 设置页视觉遵循 Figma 设计源

系统必须使 options 设置页的页面外壳、导航、现有控件及其已有状态与变更记录中的 Figma 节点保持视觉一致，实施时必须重新读取 Figma，禁止依赖提案阶段截图或记忆。

#### Scenario: 设置页页面还原

- **WHEN** 用户打开任一现有 options 设置路由
- **THEN** 页面外壳与该路由中已有内容按照设置页面稿呈现，且路由与内容保持不变

#### Scenario: 组件与状态还原

- **WHEN** 用户操作设置页中已有的控件、菜单、弹层或编辑器
- **THEN** 其现有状态按照组件规范与交互状态节点呈现，且状态转换行为保持不变

#### Scenario: 弹层与下拉规范统一

- **WHEN** 用户打开设置页中任一现有弹窗、侧边弹窗、选择器、可搜索下拉或菜单
- **THEN** 其现有内容按照对应补充规范统一呈现，且选项、事件、焦点、键盘操作与关闭结果保持不变

#### Scenario: 基础组件、侧边栏与功能示意图统一

- **WHEN** 用户浏览设置页侧边栏、现有基础控件或悬浮工具相关页面的功能示意区
- **THEN** 这些视觉元素按照最新补充组件规范统一呈现，且导航、控件和功能配置的行为保持不变

### Requirement: 设置页主题作用域隔离

系统必须将本能力的视觉规则限制在 options 文档范围内，并覆盖该文档中的默认 Portal 内容；其他扩展界面不得继承这些设置页专属规则。

#### Scenario: options Portal 继承主题

- **WHEN** options 页面打开默认挂载到当前文档的菜单、弹窗、抽屉或提示
- **THEN** Portal 内容继承当前 options 主题并保持原有挂载、层级、关闭与焦点行为

#### Scenario: 其他界面不受影响

- **WHEN** 用户打开 popup、sidepanel、content UI 或翻译中心
- **THEN** 这些界面的主题与行为不因设置页主题实现而改变

### Requirement: 明暗主题一致性

系统必须在浅色、深色与跟随系统三种现有主题模式下应用 Figma 所定义的相应设置页视觉，并继续使用既有主题状态链。

#### Scenario: 手动切换主题

- **WHEN** 用户在现有主题设置中选择浅色或深色
- **THEN** options 页面与其 Portal 内容同步呈现对应视觉，主题设置行为保持不变

#### Scenario: 跟随系统主题

- **WHEN** 用户选择跟随系统且系统主题发生变化
- **THEN** options 页面与其 Portal 内容随既有监听机制更新，且不新增主题状态或存储字段

### Requirement: 功能零变更

系统必须完整保留现有设置项、分组、导航、配置读写、校验、保存条件、权限、列表内容、事件、焦点与关闭行为；Figma 中项目当前不存在的功能或交互不得新增。

#### Scenario: 视觉更新前后行为一致

- **WHEN** 对视觉更新前后的同一设置流程执行行为回归
- **THEN** 可用操作、状态转换、持久化结果和错误结果保持一致

#### Scenario: 设计稿包含额外功能

- **WHEN** Figma 节点展示项目当前不存在的设置项、操作或状态转换
- **THEN** 实现忽略该额外功能并保留项目当前行为

### Requirement: fork 换皮边界

系统必须将新增设置页视觉实现放在 `src/fork/**`，并通过既有受控 UI 重定向接入；不得为本变更原地修改共享主题、共享基础组件或业务页面实现。

#### Scenario: 视觉实现通过 fork 接入

- **WHEN** 检查本变更的生产代码差异
- **THEN** 新增实现位于 `src/fork/**`，接缝受重定向存在性与内容指纹护栏保护

#### Scenario: 上游接缝漂移

- **WHEN** 被重定向的上游接缝移动、删除或内容发生未审查变化
- **THEN** 构建或护栏检查失败并要求人工复核
