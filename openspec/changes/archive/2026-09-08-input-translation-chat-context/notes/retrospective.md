# 输入翻译聊天上下文复盘

日期：2026-09-05。变更：`input-translation-chat-context`。分支：`feat/fork-foundation-input-trans`。

本记录依据当前会话、proposal/design/tasks、主题诊断记录与迁移验证记录自动整理。记录已实施的结果与证据边界，不把复盘完成等同于交付完成；复盘时实施任务为 **58/62**，后续提交对账进展见文末。

## 背景与目标

Discord 的网页语言主要反映界面语言，而非频道内正在使用的语言。输入翻译沿用整页源语言时，泰语等频道容易被当成英语。

本次目标是：在已登记的聊天站点中，用最近消息解析输入翻译的目的语言；允许用户通过内联条改语言重译、撤销；适配宿主主题，并控制定期合并上游时的冲突范围。

明确保留的边界：不新增配置 schema 或迁移，不改翻译引擎、provider 和输入替换协议；用户显式指定的源语言优先于自动检测。当前只登记 Discord，不修改其他页面的整页翻译逻辑。

## 遇到的问题及挑战

### 1. “源语言”名称容易与输入翻译方向混淆

- **问题**：产品描述同时出现“跟随最近聊天语言”“网页源语言”“翻译目标语言”，容易被理解成要检测用户刚输入的文本语言。
- **澄清与解法**：分别记录配置选项、解析后的语言码和翻译方向。在已登记站点且全局源语言为自动时，`sourceCode` 才使用聊天上下文；`targetCode` 仍指用户配置的目标语言，显式语言不被自动检测覆盖。
- **边界**：同语言短路比较的是解析后的 from/to，不是自动识别草稿语言。主 Chrome 补验中对泰语草稿再次触发仍可能重译，不能据此宣称同语言提示已验证。
- **经验**：需求例子应同时列出“用户配置、频道内容、输入原文、预期目的语言”，不能只写“源语言”。

### 2. 最近五条消息直接拼接，仍可能被长公告干扰

- **问题**：设计记录指出，franc 对长文本的权重会使机器人英文公告压过较短的新消息；极短日语、韩语又可能低于检测长度门槛。
- **解法**：限定最近消息窗口并清洗噪音；最新消息含假名或谚文时识别日语/韩语，否则聚合同窗口中与最新消息同文字系统的文本再检测。无法可靠判断则回退整页源语言，内联条提供人工纠错。
- **残余风险**：俄、塞、乌共用西里尔字形，中日共用汉字，不能简单按字形猜具体语言；@提及等噪音也未被完全清除。
- **经验**：检测用例必须包含长公告、短消息、混合语种和无有效文本，而不只是单语长段落。

### 3. “失焦隐藏”被实现成“结束会话”

- **问题**：用户实测发现译文生成后移开焦点，再聚焦时内联条不能恢复。仅删除 UI 状态会同时丢掉元素归属和原文快照。
- **解法**：分离翻译会话与显示状态。失焦只隐藏；原输入元素重新聚焦则恢复。Esc、撤销、实际发送或元素卸载才结束会话。
- **同时补齐**：不可变 `originalText` 保存首次触发的原文。翻译完成前的编辑属于竞态保护，应放弃替换；翻译完成后的编辑属于正常操作，应保留撤销能力。Portal 菜单属于交互范围，不能因 DOM 层级分离误判失焦。
- **证据**：迁移后主 Chrome 中，失焦恢复、修改/追加译文后撤销、清空全部译文后撤销均通过；撤销恢复最初中文原文。分层 Esc 与结束后不复活也通过。

### 4. 深色条体与共享菜单主题不一致

- **问题**：Discord 深色输入区域出现黑色语言名称和浅色菜单；条体背景、文字与 Portal 菜单没有统一的主题来源。
- **解法**：建立输入翻译局部主题和专属 Portal 容器。优先读取实测确认的 Discord 主题标记，其次判断输入区域有效背景，不能可靠判断时回退扩展主题。使用不透明底色和局部 CSS 变量，不修改用户主题配置或整个 selection Shadow Root。
- **性能约束**：只监听相关主题/祖先属性并合并更新，清理卸载监听；不用消息树全量观察或持续轮询。
- **证据边界**：配色数值测试及部分真实深浅主题观察已有记录；迁移后主 Chrome 只补验当前深色主题。完整实际文字对比度、窄窗口、长名称和其他 UI 回归仍未验收完。

### 5. 搜索框能聚焦，但按键和粘贴后被 Discord 抢回焦点

- **问题**：组件测试通过，真实 Discord 中搜索字符却进入消息草稿。只检查初始 focus 或菜单节点存在，无法发现问题。
- **定位**：临时观察消息输入框的 `focus` 调用栈，确认 `keydown` 和 `paste` 在冒泡阶段（`eventPhase=3`）被 Discord 接管，而不是扩展的失焦恢复主动抢焦点。仅修键盘后，粘贴仍失败，说明二者需要独立覆盖。
- **解法**：在 Portal 所属 ShadowRoot 的冒泡阶段，用 `composedPath()` 和容器归属限制事件来源；让 React/Base UI 先处理搜索与选择，再阻止相关事件继续到宿主。仅 `stopPropagation()`，不 `preventDefault()`、不全局拦截、不循环抢回焦点、不重放按键。
- **证据**：补充真实 ShadowRoot/Base UI 与宿主抢焦点监听的失败回归，再实施；移除临时探针后实页验证。迁移后主 Chrome 的逐键 `eng` 搜索与纯文本 `English` 粘贴均只改变搜索框，草稿不变。
- **经验**：Portal 交互需要同时审查 React 委托事件、物理 DOM 冒泡与宿主页面监听；不能把“监听位置越靠内越安全”当作默认结论。

### 6. 降低上游合并冲突，需要改变交付边界

- **问题**：最初优先考虑上游 PR，输入翻译增强与共享 Combobox 扩展分布在上游文件中；用户不定期同步上游时会持续承受文本冲突。共享选择器的 GitNexus impact 曾返回 HIGH，影响不止输入翻译。
- **解法**：用户确认 D12 后，将业务、主题、菜单和测试集中到 `src/fork/ui/selection-content/input-translation/`，fork App 仅挂载一个 fork hook。恢复上游 hook/index 及两个共享 Combobox 文件；专用菜单组合 Base UI 所需原语，复用上游语言数据、过滤、输入与列表组件。
- **代价**：没有文本冲突不代表自动获得上游修复。新增四文件 SHA-256 漂移哨兵，以已评审基线提醒人工对账；必须先移植适用修复并验证，再更新指纹，禁止自动刷新指纹掩盖变化。
- **其他偏离**：站点规则新增字段方案因其类型来自受保护 zod schema 被否决，改为独立站点选择器映射，避免 schema/配置迁移和双数据源。

### 7. 构建成功，不代表主 Chrome 正在执行新代码

- **问题**：开发服务曾出现动态注册内容脚本未恢复；文件迁移后，主 Chrome 加载的 `.output/chrome-mv3-dev` 又早于迁移，最新 production 构建不能证明旧 dev 目录已更新。仅看版本号或刷新网页会误验旧实现。
- **解法**：核对扩展详情页的实际加载目录、构建时间和 SHA-256；重启 WXT 开发服务并完成全量构建，重载扩展，再刷新 Discord。确认 dev 产物包含迁移后 fork hook 与专用菜单的模块路径。
- **本次指纹**：最终 dev `selection.js` 构建时间为 `2026-09-05T06:35:32.690Z`，SHA-256 为 `c0afdda2867245d54fa3ab84a3977be42f20616d77010905b6573026f30f40a7`。
- **经验**：扩展验收前固定执行“构建 → 确认加载目录/指纹 → 重载扩展 → 刷新宿主 → 验证真实动作”，不能只确认目录存在。

### 8. 自动化工具和检查范围也会造成误判

- **主 Chrome 控制**：曾因用户操作中断和网页连接超时未能完成实页测试。先取得的独立 profile、本地页面、真实翻译服务证据被明确标注为本地验证，后续才补齐主 Chrome 核心路径。
- **输入工具**：未指定格式的 paste 曾带入富文本链接，连续选中/输入也出现未立即生效。改为明确纯文本格式，并逐步核对实际选区、输入值后继续；这类失败尝试不记为产品通过证据。
- **菜单选择**：`eng` 同时匹配英语与壮语，盲目 Down + Enter 可能选错。测试应断言真实高亮项或使用唯一结果，不修改产品过滤规则迎合脚本。
- **图谱与 diff**：新增 fork 文件尚未跟踪，普通 diff/stat 与部分 graph 检查不能代表完整变更。历史验证使用隔离临时 Git index 纳入新增文件，保留用户实际暂存区；图谱流程裁剪仍需明确说明，不把“0 affected processes”当作无影响。
- **测试环境**：本地使用 `SKIP_FREE_API=true`，官网环境变量仅在测试命令中覆盖，不删除用户 `.env`。既有导航提示、大 chunk 告警与产品失败分开记录。

## 架构/设计偏离说明

| 原计划或早期理解            | 最终选择                                  | 原因与后续责任                                                           |
| --------------------------- | ----------------------------------------- | ------------------------------------------------------------------------ |
| 站点规则增加聊天字段        | fork 独立消息选择器映射，复用已有排除规则 | 避免修改受保护 schema；后续新增站点仍须验证真实消息选择器                |
| 失焦关闭即销毁状态          | 会话状态与可见状态分离                    | 支持恢复与不可变原文撤销；元素卸载和实际发送需独立收尾                   |
| 共享语言选择器增加参数      | fork 专用菜单组合未修改的上游原语         | 缩小共享组件冲突面；保留 Portal、事件与默认行为测试                      |
| 上游 PR 为主，fork 为后备   | D12 明确启用 fork 自持路径                | 符合当前同步策略；四文件指纹失败后必须人工移植和回归                     |
| 组件测试/构建可支撑交付结论 | 按产物、profile、宿主和场景分别记录证据   | 本地 production 验证不能替代主 Chrome dev，更不能替代生产包 Discord 验收 |

语言解析仍在调用层、位于方向互换之后；翻译引擎、配置、provider 和输入替换协议保持复用，这些不属于偏离。上述主要调整已进入 design D2、D7–D12，本次复盘不追加新的产品需求。
