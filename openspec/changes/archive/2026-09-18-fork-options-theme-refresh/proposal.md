## Why

现有设置页的视觉主题与最新 Figma 设计稿不一致，且页面、基础控件、弹层和交互状态缺少统一的设置页视觉边界。本变更以最新设计稿为唯一视觉权威源，在不改变任何功能、数据或交互行为的前提下统一设置页外观。

## What Changes

- 按变更记录中的页面、组件、交互状态、弹窗、侧边弹窗与下拉选项 Figma 节点，更新设置页的明暗主题、页面外壳、导航、现有控件及其已有状态的视觉呈现。
- 为设置页建立 fork 专属视觉作用域，使默认挂载到文档的菜单、弹窗、抽屉和提示能够继承同一主题，同时不影响 popup、sidepanel、content UI 与翻译中心。
- 完整保留现有设置项、分组、导航、配置读写、校验、保存条件、权限、事件、焦点与关闭行为；设计稿独有而项目当前不存在的功能或交互不纳入实现。
- 建立页面、控件和状态与 Figma 节点的视觉核对清单，并覆盖浅色、深色与跟随系统主题的真实界面验收。

## Capabilities

### New Capabilities

- `fork-options-theme`: 规定 fork 设置页独立视觉主题的作用域、Figma 还原范围、功能零变更边界和回归验收要求。

### Modified Capabilities

无。

## Impact

- 主要影响 options 设置页外壳及 `src/fork/**` 中的设置页专属视觉实现；复用现有 ThemeProvider、路由、配置状态和共享组件行为。
- 需要通过受控 UI 重定向接入 fork 设置页外壳，并同步维护重定向指纹护栏。
- 不修改配置 schema、存储格式、迁移链、消息协议、API、权限或其他插件界面的业务逻辑；仅增加用于视觉还原的 Onest 字体资源依赖。
- 用户可见变更需要为 `@read-frog/extension` 增加 changeset。

## 最终范围补充（2026-09-18）

用户在实施复核中明确要求统一所有共享输入框、Dialog 和抽屉的视觉，因此允许共享组件样式及受控白名单接缝更新；原文中其他扩展界面完全不受影响、禁止修改共享组件的限制，以此授权范围为准。页面标题、说明文字和展示分组按设计调整，业务设置、状态转换、事件、数据及校验保持不变。

最终确认要求：输入框及文本框的 hover、聚焦和输入态保持默认视觉；普通 Dialog 与确认弹窗在当前页面上使用 15% 半透明蒙层；下拉菜单按内容扩宽，窄屏长选项换行。上述用户明确修订优先于原始设计稿中的状态示例。
