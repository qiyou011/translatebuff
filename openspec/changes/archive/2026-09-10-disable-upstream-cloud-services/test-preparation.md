# 任译喵上游云服务隔离：功能影响与测试准备

日期：2026-09-10

关联变更：`disable-upstream-cloud-services`

开发分支：`feat/disable-upstream-cloud-services`
面向人员：产品、测试、开发及提测负责人

> 当前状态：设计已通过架构复审，代码已实施，部分验收待完成；实施与验证证据见 [implementation.md](./implementation.md)。本文是提测准备清单，不是测试通过报告，也不代表下述功能已发生故障。提测版本号及构建提交以实际安装包记录为准。

> 包体提醒：现有 `.output` 产物早于最后一次语言检测异常降级修复，不能作为本次最终验收包；需从最终提交重新构建。海外测试构建尚缺 `.env.global`，不能用海外正式配置包冒充测试包。

## 一、变更说明与测试结论口径

本次关闭任译喵不使用的上游账号、托管 AI、云转录、云笔记和博客通知服务，停止扩展内这些功能对 `/api/identity`、`/api/rpc`、`/api/blog` 的请求。保留上游核心翻译逻辑、任译喵登录会员体系及现有非上游模型服务。

测试范围应为“翻译功能整体回归 + 旧配置兼容 + 上游云功能关闭”，不能只检查三个接口是否停止请求。

- 应保留的功能：与改造前保持一致；旧配置兼容和语言检测降级按本文约定验收。
- 主动关闭的功能：入口和请求消失属于预期，不作为功能丢失缺陷。
- 非目标：不恢复当前已隐藏的模型或功能入口，不改自有接口域名，不清理用户历史数据。
- 计费边界：兼容到任译喵模型后仍使用正常额度规则，不代表免费；正式环境不执行未授权支付或其他收费验证。

## 二、应保留的功能及回归重点

| 编号 | 功能点                 | 回归重点与预期                                                                                                                           |
| ---- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| F01  | 页面翻译               | 启动翻译、译文切换/恢复、页面标题、目标语言内容跳过正常；旧模型配置不导致整页卡死                                                        |
| F02  | 划词翻译               | 正常生成与流式输出、切换模型、错误提示、加载结束正常                                                                                     |
| F03  | 输入翻译 / Discord     | 三空格触发、最近聊天语言识别、切换目标语言重新翻译、修改/新增/删除译文后撤销回最初原文、失焦再聚焦恢复内联条、语言菜单搜索不误写消息草稿 |
| F04  | 视频字幕               | 原生字幕提取、翻译、切换字幕源及译文字幕下载正常；摘要/分段仅对支持 LLM 的模型验证                                                       |
| F05  | 语言检测               | 普通文本、页面和聊天上下文检测正常；旧上游模型降级本地，有效非上游 LLM 按原开关及能力工作                                                |
| F06  | 自定义动作与内置词典   | 合格模型正常生成、参数正确、失败后结束加载；不出现上游登录/购买提示                                                                      |
| F07  | 模型设置与实际模型展示 | 有效配置不被新逻辑替换；临时兼容后的展示、请求参数与实际模型一致，不复用旧托管模型身份的缓存                                             |
| F08  | 任译喵账号与会员       | 登录、会话恢复、凭据获取/过期、额度查询/不足及登出保持原行为；上游无会话不清除任译喵登录态                                               |
| F09  | 官网联动及自有服务     | 官网认证联动、会员入口、原有跳转与上报保持原行为；自有接口域名及协议不变                                                                 |
| F10  | 弹窗、设置页及引导     | 正常打开，无白屏、持续加载或已关闭云功能的残留入口；正常会员菜单保留                                                                     |

补充间接回归：调用关系分析发现语言检测还关联翻译中心的语言自动识别、朗读时的语音语言选择、页面同语言跳过判断。当前发行版有入口时执行验证；无入口则注明“不适用及原因”，本次不恢复这些入口。

## 三、主动关闭的功能

| 编号 | 功能点                      | 正确结果                                                               |
| ---- | --------------------------- | ---------------------------------------------------------------------- |
| D01  | 上游账号登录及会话刷新      | 无入口、无认证请求、无刷新订阅；任译喵账号正常                         |
| D02  | 上游托管 AI、配额及购买引导 | 不请求上游托管服务，不展示相关引导；普通翻译按旧模型兼容规则处理       |
| D03  | 上游云转录                  | 关闭；不得连带关闭原生字幕提取与翻译                                   |
| D04  | Notebase 云保存             | 不执行，不伪装保存成功；旧待保存数据保留，重启或 Cookie 变化后也不发送 |
| D05  | 上游博客更新通知            | 不查询、不展示；旧缓存不能重新产生更新提示                             |
| D06  | 笔记建议                    | 当前 fork 已关闭，保持无入口、无生成调用，不自动分配替代模型           |

## 四、必须准备的配置组合

说明：“旧上游模型”指历史配置中选择的上游托管模型（system provider）；“合格任译喵模型”指已有配置中启用、能力匹配且满足现有凭据门控条件的模型。凭据存在不代表服务端权益或额度有效。

| 编号 | 配置或状态                               | 操作与预期                                                                                                                                     |
| ---- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| C01  | 已选择有效任译喵或当前支持的自配模型     | 发起翻译，使用原模型，不被兼容逻辑替换                                                                                                         |
| C02  | 旧上游模型 + 一个合格任译喵候选          | 请求前临时使用该候选，正常出结果，不持久化替代选择                                                                                             |
| C03  | 旧上游模型 + 无合格候选                  | 提示登录/选择模型，不请求上游、不自动重试、不持续加载                                                                                          |
| C04  | 候选被禁用、缺凭据或能力不匹配           | 分别测试，不错误选中不合格候选；全部不合格时同 C03                                                                                             |
| C05  | 多个合格候选                             | 按配置顺序选择首个，展示、参数、统计及缓存身份一致                                                                                             |
| C06  | 语言检测选择旧上游模型                   | 降级本地检测，不自动调用收费模型；生成/RPC 调用次数均为零                                                                                      |
| C07  | 已明确选择有效非上游 LLM 检测模型        | 按原 LLM 开关和能力工作；开发另验证显式 local 引用优先于旧持久化选择                                                                           |
| C08  | 候选凭据已过期或额度不足                 | 沿用原有凭据/权限/额度处理，不误判会员、不改换其他收费服务                                                                                     |
| C09  | 正常任务与禁用任务并存                   | 禁用任务结束，不能连带终止同队列中的正常翻译                                                                                                   |
| C10  | 旧配置升级后直接使用                     | 升级、重载或冷启动后，不打开弹窗/设置、不重新登录，直接翻译；兼容无需这些操作激活                                                              |
| C11  | 存在旧博客缓存和旧云笔记任务             | 打开 UI、重启后台、发生会话变化；不出现通知、不执行保存、不删除待保存数据                                                                      |
| C12  | LLM 检测开启、未传显式模型且配置读取失败 | 开发协助模拟读取失败：普通语言检测继续本地识别，直接 LLM 返回空且不发生成请求；显式有效 local 仍正常调用。关联回归翻译中心自动识别及朗读选音色 |

优先将 C01、C02、C03、C10 与页面、划词、输入、字幕及自定义动作交叉验证。语言检测单独按 C06/C07 验收，不套用收费模型兼容规则。

配置前后对比须区分两件事：本次运行时兼容不新增写回；原有模型种子、登录和凭据同步仍可按既有逻辑更新配置，不能把所有正常写入判为缺陷。

发行版和环境要求：

- 国内、海外 Chrome 测试包执行功能回归与网络验证；正式配置包执行无副作用的服务隔离检查。
- 开发环境同样适用三类服务禁用策略，不能仅正式构建生效。
- 开发提供 Edge/Firefox 既有构建检查结果；构建通过不等于这两个浏览器已完成真实功能验收。
- 缺账号、配置、模型权限或页面条件的项目标记“待验收”，不能用单元测试或构建结果替代。

## 六、网络与开发侧补充验证

网络验收必须覆盖扩展 Service Worker、扩展页面和内容脚本的实际触发路径，不能只看普通网页的 Network。

1. 冷启动、重载、打开弹窗/设置、会话变化、旧配置恢复及功能调用时，上游功能链路对 `/api/identity`、`/api/rpc`、`/api/blog` 前缀本身及子路径均为零请求。
2. 不仅检查上游域名：即使路径挂在任译喵域名下，上游功能链路也不得请求。
3. 自有登录、额度、翻译及上报请求正常；不得按浏览器全局路径黑名单误拦普通网页或用户自配服务的同名路径。
4. 不出现重试风暴、持续轮询、加载不结束或假成功。

以下项目由开发提供自动测试/诊断证据，测试同事不必只靠手工 UI 验证：

- 显式旧模型快照绕过常规解析时仍在请求前处理；同步候选判断无网络、存储或会员刷新副作用。
- 语言检测三个入口均覆盖，禁用路径在原三次尝试前结束，生成与 RPC 零调用。
- 配置读取失败的 C12 由开发提供故障注入或自动测试证据，不通过删除真实用户配置制造故障；测试侧同时回归正常语言识别、翻译中心与朗读入口。
- 流式端口仅传错误文本时，禁用仍在请求前收敛；正常/禁用任务并存不误伤共享队列。
- 最终模型的参数、温度、缓存、统计与展示一致；新增兼容不写配置，原同步行为不变。
- 冷启动无新增模块依赖循环，内部函数调用不绕过 fork 包装。
- 原测试与 fork 重定向测试、类型/格式、边界/指纹及构建检查通过。`SKIP_FREE_API=true` 跳过的外部在线测试须单列，不算在线服务验证通过。

## 七、执行顺序与验收记录

建议顺序：旧配置升级 → 页面/划词/输入 → 语言检测 → 登录会员 → 字幕/动作 → 云功能关闭及网络检查。

每项结果使用“通过 / 失败 / 待验收 / 不适用”，并附原因或证据。建议记录格式：

| 用例编号 | 版本/构建提交 | 发行版/环境/浏览器 | 账号状态/配置编号 | 实际结果 | 状态   | 截图/日志/缺陷编号 |
| -------- | ------------- | ------------------ | ----------------- | -------- | ------ | ------------------ |
| 待填写   | 待填写        | 待填写             | 待填写            | 待填写   | 待验收 | 待填写             |

验收关注：保留能力无回归、旧配置符合约定、关闭能力不再触发、正常业务不受牵连、用户数据未误删。不能将“零请求”单独作为整体通过标准；架构评审、自动测试、构建和真实浏览器结果分别记录。

分享配置或网络日志前须脱敏，不能包含账号密码、Cookie、会员 token、API key 或用户私人消息。
