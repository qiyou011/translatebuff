# fork-options-feature-provider-gating

## Why

未登录（或登录但网关 key 尚未注入）时，任译喵网关模型没有可用凭据，点它翻译必然失败。但在选项页「通用」页的「功能提供商」里，该模型仍作为可选项裸露给用户，只在标签旁挂一个「设置 API Key」的上游警告——用户看得到、选得中一个用不了的东西，是误导。

popup 面已经做了门禁（无 key 时隐藏任译喵、只有它可选时改显登录引导），但选项页「通用」页走的是上游宿主、没有门禁，两处行为不一致。本变更把同一门禁扩展到选项页「通用」页，并把两面共用的门禁判定收敛为单一实现，避免同一逻辑两份拷贝、改一处漏一处。

## What Changes

- **选项页「通用」页门禁**：功能提供商各行在无可用 key 时隐藏任译喵项；某功能过滤后已无其它可选（或当前选中的正是被隐藏的任译喵）时，用登录引导替换该行选择器，行为与 popup 一致。非任译喵 provider 的缺 key 提示保持上游原样。
- **共享门禁抽象**：把 popup 与选项页共用的「按可用性过滤 provider + 判定是否改显登录引导」收敛为单一 fork 逻辑，两面复用、单点维护、单点测试。
- **seed 对齐**：选项页「通用」页挂载时也确保任译喵实例已就位，与 popup、选项页「API 提供商」页对齐，消除首装直开「通用」页时的门禁失效缺口。
- **上游宿主换皮**：选项页功能提供商宿主经构建期重定向顶替为 fork 版，不编辑上游源文件。

## Capabilities

### New Capabilities

- `fork-provider-membership-gating`: 未登录/无可用 key 时，对任译喵网关模型在功能提供商选择面的门禁行为——隐藏不可用项、无其它可选时改显登录引导、并保证门禁前置的 seed 就位；跨 popup 与选项页「通用」页统一。

### Modified Capabilities

<!-- 无：popup 现有门禁此前未成文规格，本变更以新能力统一描述门禁行为并落地选项页面。 -->

## Impact

- **代码**：净新增 fork 宿主与共享门禁逻辑（`src/fork/**`）；`wxt.config.ts` 新增一条构建期重定向（allowlist 内）。不编辑上游源文件、不动上游 config schema / DEFAULT_CONFIG / 后端门禁（会员态仍服务端裁决，前端仅 UI 遮蔽）。
- **不影响**：seed / repoint 配置逻辑一行不改（门禁仅在展示层过滤，实例仍在 config 中作为 repoint 靶子）；popup 顶部登录横幅与既有行为不变（DRY 抽取为行为等价替换）。
- **测试参考**（一模块一行）：
  - 共享门禁逻辑：无 key 过滤任译喵 / 过滤后为空触发引导 / 选中即任译喵触发引导 / 有 key 不过滤 / 非任译喵不受影响。
  - fork 宿主：三态展示（未登录引导 / 登录待取占位 / 有 key 列表）/ 非任译喵缺 key 走上游警告 / custom actions 空列表不渲染。
