# 网页双语格式保留技术设计

## Context

目标是在原网页保持可用的前提下，为谷歌、微软双语译文恢复正确的局部格式。技术栈沿用 TypeScript、WXT、DOM API、现有翻译队列与缓存、Vitest；不新增框架。用户最新决定不采用微软官方认证通道；使用现有免费服务继续实施，不新增资源和费用依赖。

2026-11-13 用户确认方案，architect-review 明确“审查通过”。本设计落实该审查的批处理入口、虚拟段落、原子校验、缓存和证据约束。原型及其 SHA-256、27 组规则见 acceptance-matrix.md。原型目标效果是模拟，不是已通过的产品验收；原型历史流程文字不作为本次操作指令。

当前普通请求位于 src/utils/host/translate/core/translation-request.ts，双语插入默认 textContent，可通过 renderTranslatedContent 扩展。translation-modes.ts 的 translateVirtualParagraph 直接发送 unit.text，需要显式接入。微软 api/microsoft.ts 与 src/fork/page-translation/queues.ts 都拒绝 HTML。dom/inline-atoms.ts 既有缺失公式末尾补回行为不满足新路径“不猜位置”，不能无条件复用。

## Goals / Non-Goals

目标：完整段落上下文、原型 P0 子项、用户颜色优先、安全重建、两层缓存和动态生命周期一致；P1 独立记录。非目标：仅译文及大模型新适配、评审页面本身的导航／模拟控件、面板改版、文档翻译、账号收费、任意样式完整克隆。没有 Figma 资源，本变更不生成 Figma 还原任务。

## Decisions

### D1：分别适配服务，共享可校验的格式描述

比较方案一“统一标记协议”与方案二“服务独立适配、共享规则”。前者逻辑集中，但把两个服务的标记可靠性绑定；选择用户已确认的方案二，允许线协议不同，结果契约相同。禁止逐个格式片段独立翻译，禁止用字符串位置推断中译文对应。

共享提取层以现有段落分割结果为边界，生成正文、格式树与原子表；格式树包含嵌套关系及确定性局部编号，不含可执行属性。保留可见换行语义，源码空白是否有意义由内容层判断。标签及计算样式共同识别普通粗体、高亮，读取必要样式时避免重复布局计算；纯红字不作为必须保留原字色的条件。不重做整页 DOM 克隆。

### D2：按用户最新决定使用现有免费通道继续实施

2026-11-13 用户明确“不采用，你继续完成需求”：不采用 Azure 官方认证通道，不再将资源、账号或额度作为本需求前置条件。此前官方通道仅有离线准备，真实调用为 0；保留 evidence/official-channel-* 作为历史记录，不参与当前交付。

谷歌使用现有 HTML 传输，将整段格式编码为最小标签与局部 ID；微软使用现有 Edge 免费接口的独立最小无属性标签传输；格式 ID 编码为固定长度的标签序列，响应仅用于解析，绝不直接插入 DOM。通用纯文本调用仍转义正文，通用 HTML 禁止分支不变。前期成对文本标记方案已替换。两者共享格式清单、原子清单、严格校验和白名单 DOM 重建。通用微软 HTML 禁止保护保持不变。

此前真实实验已发现文本标记在部分语言和句子上的丢失及语义错位，不能将计数正确视为语义正确。本轮依用户要求继续完成集成与浏览器验证，不再等待新资源；这些反例继续作为回归约束，最终双服务正常 P0 验收门槛不降低。未通过项必须保留未完成状态，不能以降级或单服务通过宣称完成。

格式错误在队列停止重复协议重试，由所属段落至多发起一次保留原子的纯文本恢复。恢复结果标为 degraded，禁止进入正常缓存；原子仍损坏则 failed，不追加到末尾。正常请求与恢复都保持完整段落上下文。

### D3：内部数据及接口契约

以下为拟新增内部契约，字段可沿现有类型组织，不新增公共 API 或数据库表：

| 对象       | 必要字段与约束                                                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 格式源单元 | sourceText、formatTree、atoms、visibleBreaks、formatFingerprint、rulesVersion；序列化确定性，原始节点仅保存在当前内容脚本请求上下文 |
| 请求快照   | provider、sourceLang、targetLang、mode、sessionId、sourceRevision、formatFingerprint；节点移除／变化后失效                          |
| 服务结果   | translatedText、formatMapping、atomMapping、status；status 区分 normal/degraded/failed；无法验证的原始返回不当作成功对象            |
| 原子表     | 本单元内唯一 ID、种类、原文、允许的安全结构；不允许服务新增原子或改变内容                                                           |
| 格式映射   | 本单元格式 ID 与译文片段边界，支持重排及合法嵌套；未知、重复、交叉或缺失必须分类处理                                                |

服务响应先规范化与结构校验，再准入缓存和安全渲染。正常结果必须满足原子完整性及格式映射约束；仅标记计数相同不能证明语义准确，语义对应须在真实双服务验收中检查。

### D4：安全重建、样式与失败状态

采用 DOM API 创建新译文节点。格式允许范围覆盖 strong/b、mark、安全 span 表达的粗体／高亮，以及 P1 em/i/u/del；code/kbd/samp/sup/sub 和本次 MathML 按原子策略安全恢复。结构性段落、列表、表格仍留在原容器，不复制整张表或控件。原子克隆须清理脚本、事件、ID 和不必要属性；公式的必要结构单独白名单，不以放行任意 SVG/HTML 换取保真。

必要样式仅允许本能力需要的字体类别、强调、装饰与背景色，不复制 URL、定位、任意 class 或交互属性。译文用户字色在子节点一致生效，不覆盖高亮背景；沿用现有 src/fork/config/translation-color.ts 和样式注入策略。标题／正文尽量继承源字体，代码等宽，中文缺字回退在浏览器验证。恢复不会复制链接或控件，原网页链接保持可用。

格式异常但完整正文和全部原子对应可确认时，剥离损坏格式并返回 degraded；不能确认正文完整或原子位置时追加一次纯文本恢复请求，仍按原子标记校验。恢复请求不再次触发格式恢复循环，复用现有传输重试上限并遵守取消和页面时效检查。再次失败进入既有失败状态；不追加缺失公式到末尾、不显示占位符、不以缺文结果伪装成功。

### D5：缓存与并发

沿既有内存、后台持久缓存及批处理去重扩展确定性身份：服务身份、实际语言方向、模式、规则版本、源文字及格式／原子描述。仅请求实例 ID 不进入稳定缓存键；局部确定性编号允许同文同格式安全复用。传输若要求随机标记，入缓存前归一为局部 ID，读取后绑定当前请求。

校验必须先于所有成功缓存写入，包括后台队列；不能仅在 DOM 端发现问题。失败和损坏原始响应不写成功缓存，降级结果不写正常格式缓存。本期可不缓存降级结果，避免永久固化格式丢失。读取缓存也校验版本与原子／格式身份，不缓存原始 DOM 引用；规则版本变化自然失效旧条目，无需清空其他功能缓存。

复用现有 session 和 isCurrent 守卫，在请求前、响应后、渲染前及异步装饰后检查。正文变化、节点移除、服务／模式切换及恢复原文使旧请求失效；普通与虚拟段落均如此。仅更新插件拥有的译文节点，避免观察器把自身插入当作新原文；每个当前单元最多一个译文。样式变化导致格式描述变化时须失效对应结果，不把仅文本相同视为同一格式源。

## Risks / Trade-offs

- 初步图分析 CRITICAL，索引落后且截断；实施前更新索引，具体符号限定查询并完整分页，UNKNOWN 需文本核实，不能拿零调用当安全。提交前 detect_changes 必须完整。当前仅文档变更，不据此宣称代码风险消除。
- 工作区已有未提交样式、配置等改动：建立基线清单，隔离本变更，避免覆盖用户工作；跨任务的字色实现按当前文件整合。
- 协议可靠性和翻译质量不由单元测试证明：每服务独立真实验收；字体缺字、隐藏辅助文字和原站条件保留具体证据，不做全网站泛化。
- 回滚以撤回本能力专用接入、恢复旧双语请求和渲染为单位，保留用户配置，规则版本隔离缓存；不新增用户开关。保留可行性实验与失败证据，不回滚其他任务改动。

## Validation

本地测试命令统一先设 `$env:SKIP_FREE_API='true'`，执行 `pnpm exec vitest run <对应测试路径>`；先跑新增契约及普通／虚拟段落、缓存、恢复用例，再跑 `pnpm test`、`pnpm type-check`、`pnpm build`。预期新增与既有测试通过，free-api.test.ts 有意跳过。已有基线失败单独记录，不伪称全部通过。仅对本次文件执行格式检查，遵守项目 fork 边界检查，不自动重写来源账本。

真实验收逐组进入视口等待翻译，记录 normal/degraded/failed/unverified，涵盖原型全部 P0 子项、原站与受控页、双服务、字色／字体、动态更新、重复翻译、切换与恢复。真实请求只使用批准的测试文本，不上传用户页面隐私内容。既有 Edge/Google 前置实验已留证，正式浏览器验收尚未执行；官方认证通道目前只有离线准备，不与前置实测混淆。
