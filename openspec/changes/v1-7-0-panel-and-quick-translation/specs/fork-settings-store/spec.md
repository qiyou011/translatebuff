## MODIFIED Requirements

### Requirement: fork 独立迁移链

系统 SHALL 为 fork 配置维护独立版本与迁移链，与上游 schema 解耦。主配置初始化完成后，后台唯一入口 MUST 读取其稳定快照，完成 fork 升级、校验及持久化后释放初始化屏障；页面读取不得各自触发写迁移。

#### Scenario: 旧版本 fork 配置被迁移

- **WHEN** 后台读取缺失或低版本 fork 配置
- **THEN** 迁移为当前 schema 并保存，统一初始化两次空格，保留间隔；具体输入目标保留，旧跟随网页/聊天或全局目标引用解析成当前用户全局目标语言后独立保存；禁用轮换

#### Scenario: 后续启动与恢复中断

- **WHEN** 已完成迁移的用户修改次数后再次启动，或上次升级中断
- **THEN** 前者保留用户值，后者幂等完成升级；版本标记不得先于有效数据提交，旧快照不得覆盖并发修改

#### Scenario: 读取时按需迁移并回写

- **WHEN** popup、options 或 content script 读取配置
- **THEN** 等待后台初始化完成并订阅同一存储变化；不能在缺失状态下各自保存默认值

## ADDED Requirements

### Requirement: 备份和重置覆盖功能配置

系统 SHALL 为本地备份携带主配置与有版本的 fork 功能配置，导入先校验再应用；会员鉴权状态不由配置备份恢复。旧备份 MUST 按同一规则补齐缺失的功能配置。

#### Scenario: 新旧备份导入

- **WHEN** 导入新版完整备份或旧版仅主配置备份
- **THEN** 新版保留有效次数和独立语言；旧版按导入的主配置初始化缺失功能值并采用两次空格；导入属于显式恢复操作，不将已有 fork 状态意外混入旧备份

#### Scenario: 重置范围明确

- **WHEN** 用户重置全部设置或仅特定功能
- **THEN** 全部重置覆盖主配置和 fork 功能设置，单功能仅重置指定范围；同步通知各端并使不再有效的请求失效，不修改登录凭据

#### Scenario: 失败恢复

- **WHEN** 导入校验失败或跨存储写入中断
- **THEN** 不暴露半套配置，保留恢复快照并阻止消费，完成恢复后再开放；不得把失败宣称为成功
