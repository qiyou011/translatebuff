## MODIFIED Requirements

### Requirement: 输入框上方提供内联纠正入口

翻译完成并成功替换输入内容后，系统必须在输入框上方显示内联条，展示本次使用的目标语言、配置或临时选择来源，并提供手动改语言与撤销两个操作。

#### Scenario: 自动检测成功

- **当** 草稿语言检测成功并按用户目标语言完成翻译
- **则** 内联条必须显示该目标语言并标注「已设置」

#### Scenario: 临时修改目标语言

- **当** 用户在完成条修改目标语言重译成功
- **则** 内联条必须标注「手动选择」，不自动改变持久目标配置

#### Scenario: 回退到整页源语言

- **当** 旧配置或旧调用尝试在草稿识别失败后回退网页语言
- **则** 本次新规则禁止该回退；保留草稿、显示识别失败提示，不生成成功条；旧目标引用由升级过程转换为用户目标快照

#### Scenario: 用户手动改语言

- **当** 用户在内联条中选择另一种语言
- **则** 系统必须以**原始输入文本**重新翻译，并替换输入框内容

#### Scenario: 用户撤销

- **当** 用户点击撤销
- **则** 输入框必须恢复为翻译前的原始文本

#### Scenario: 用户编辑译文后撤销

- **给定** 用户连续按已配置次数的空格触发翻译，系统已成功替换输入内容并保存触发时的原始文本
- **当** 用户对译文执行删除、修改或新增内容后点击撤销
- **则** 输入框必须恢复为触发翻译前保存的原始文本，不得恢复为任何编辑后的译文或中间状态
- **且** 用户对译文的上述编辑不得改写撤销所使用的原始文本快照，也不得仅因内容发生变化而使内联条消失

#### Scenario: 焦点真正离开后暂时隐藏内联条

- **给定** 翻译成功后内联条正在显示
- **当** 焦点从输入框及内联条交互范围移到外部元素
- **则** 系统必须暂时隐藏内联条，但继续保留该输入框的原始文本快照与会话归属
- **但是** 焦点进入内联条、语言选择器或其弹出菜单不算失焦，内联条必须继续保留

#### Scenario: 重新聚焦原输入框后恢复内联条

- **给定** 翻译内联条因真正失焦而暂时隐藏，且原输入元素仍在文档中
- **当** 用户重新聚焦当初触发翻译的同一个输入框
- **则** 系统必须重新显示该内联条，并继续使用原有的不可变原文快照
- **但是** 聚焦其他输入框不得显示或复用这次会话的内联条

#### Scenario: 消息实际发送后关闭内联条

- **给定** 翻译成功后内联条正在显示
- **当** 用户将当前输入框中的消息实际发送
- **则** 系统必须关闭内联条
- **且** 再次聚焦原输入框时不得恢复本次已结束的内联条
- **但是** 换行或其他未提交消息的按键操作不得关闭内联条

#### Scenario: 按 Esc 关闭内联条

- **给定** 翻译成功后内联条正在显示
- **当** 语言菜单未展开且用户按 Esc
- **则** 系统必须关闭内联条
- **且** 再次聚焦原输入框时不得恢复本次已结束的内联条

#### Scenario: 语言菜单展开时按 Esc

- **给定** 内联条的语言菜单正在展开
- **当** 用户第一次按 Esc
- **则** 系统必须只关闭语言菜单并保留内联条
- **且** 未提交选项且焦点仍在本菜单内时，关闭后焦点必须回到可用的语言按钮；不得因菜单卸载时的焦点空档隐藏条
- **但是** 已在外部输入框、同一 ShadowRoot 的其他控件或仅在 shadow host 上的焦点不得被强行拉回

#### Scenario: 翻译期间用户修改了输入

- **当** 首次翻译返回时输入框内容已被用户改动，系统放弃替换
- **则** 系统必须不显示内联条，以免撤销操作覆盖用户的新输入

#### Scenario: 页面存在多个输入框

- **当** 用户在主输入框翻译后，将焦点切换到另一个输入框
- **则** 原内联条必须隐藏且不得显示到另一个输入框；重新聚焦主输入框时必须恢复
- **且** 撤销必须只作用于当初执行翻译的那个输入框；若该元素已不在文档中，撤销必须不产生任何写入

### Requirement: 请求结果不得覆盖已结束会话或新草稿

首次草稿语言识别、首次翻译、重试与重译必须共用请求有效性规则；原文快照必须保存触发序列前用户输入的首尾空白，不得以规范化后的译文输入替代。

#### Scenario: 内联操作保持反馈和写回连续性

- **给定** 用户正在当前输入框、内联条或其专属语言菜单中操作
- **当** 用户选择语言或通过鼠标、键盘激活重试，菜单关闭或操作控件被禁用、移除
- **则** 必须在动作阶段将焦点交还原输入框，持续显示翻译中反馈；成功结果无需用户额外点击输入框即可写入
- **但是** 用户随后主动离开时不得抢回焦点，仍按失焦结果暂存规则处理

#### Scenario: 焦点交接中会话失效

- **当** 同步聚焦触发空草稿会话清理、会话替换、路由或草稿变化、元素卸载或其他请求启动
- **则** 必须终止旧动作，不再发布旧会话 pending、不发起旧会话请求或写入旧原文
- **但是** 仅因原框重新聚焦而更新显示状态不得阻止有效操作

#### Scenario: 请求期间撤销或结束会话

- **当** 用户撤销、在菜单关闭时按 Esc、实际发送消息、移除输入元素、切换路由或开启新会话
- **则** 旧请求的成功、失败与清理必须不得修改新会话或新请求；撤销必须立即恢复最初原文
- **且** 首次尚无内联条时也必须能够使旧请求失效

#### Scenario: 请求期间用户编辑或编辑后改回

- **当** 用户在 pending 期间编辑输入，即便随后改回相同文本
- **则** 必须放弃旧结果，不覆盖草稿；已有成功条恢复非 pending 的成功语言并继续保留最初原文撤销，首次请求不生成纠错条

#### Scenario: 触发空格之间粘贴或拖放

- **当** 用户在连续空格序列中通过粘贴、拖放、输入法或其他非空格编辑改变草稿
- **则** 必须重置触发计数和快照；下一段按配置次数连续按空格保存新的完整原文，撤销不得丢失这些编辑

#### Scenario: 失焦时结果返回

- **当** 请求成功时焦点已离开原输入框及交互范围
- **则** 只暂存当前请求结果，不抢焦点写入；重新聚焦原框且请求、路由、草稿仍有效时才提交
- **且** 失焦不永久结束会话，暂存期间撤销与请求失效仍生效

## ADDED Requirements

### Requirement: 输入源识别草稿且目标由用户设置

系统 SHALL 自动识别当前草稿的源语言，使用用户设置的具体目标语言；MUST NOT 使用聊天或网页语言决定任一端，不再交换方向，不区分新老用户。成功检测后使用具体语言码调用既有引擎。

#### Scenario: 用户目标始终优先

- **WHEN** 用户目标为英语，在不同语种对话中输入中文或日语
- **THEN** 源语言来自草稿，目标始终为英语；临时重译选择不改变保存目标

#### Scenario: 无法识别输入

- **WHEN** 草稿语言无法可靠识别
- **THEN** 退出等待，保留原文并显示“无法识别输入语言，请补充内容后重试”，不调用翻译，不以网页或聊天语种兜底

#### Scenario: 检测期间会话失效

- **WHEN** 识别返回前用户编辑、切会话或取消
- **THEN** 丢弃旧结果，不启动翻译、不更新新会话状态

### Requirement: 空格次数统一可配置

系统 SHALL 仅以空格触发，次数允许 2、3、4、5；本次升级统一采用 2，此后保留用户选择；间隔沿用已有设置，教程与实际行为必须一致。

#### Scenario: 升级与调整

- **WHEN** 完成本次升级后用户改为 4 次并重启
- **THEN** 4 次触发、教程显示 4 次，不因重启再次变成 2 次，其他键和不足次数不得触发

### Requirement: 六平台上下文与输入框归属

系统 SHALL 支持 Discord、Telegram、YouTube、X、WhatsApp、Reddit 的适用聊天、评论或发帖输入场景；模型上下文仅来自当前编辑器所属对话或帖子并排除用户名、时间戳等噪音。上下文不得改变目标语言，不得误取其他编辑器草稿；普通提供商不启用模型上下文。未知上下文可为空，源语言仍识别草稿。

#### Scenario: 多输入框与会话切换

- **WHEN** 页面有多个编辑器或使用同一 DOM 切换会话
- **THEN** 请求绑定元素及会话标识；上下文与写回只作用于所属编辑器，旧会话结果不得写入新会话

#### Scenario: 平台说明

- **WHEN** 打开输入面板或完整设置
- **THEN** 展示六个平台名称及可访问的品牌图标，完整设置的平台模块位于触发设置之前；国内展示原型指定使用说明，海外不展示国内说明

### Requirement: 请求开始即提供等待反馈

系统 SHALL 在草稿识别和翻译开始时立即显示同一位置的等待浮窗，保留原文及正式品牌标识，不展示虚构进度；完成条显示 MUST 与语言来源解耦，固定目标同样提供重译与撤销。

#### Scenario: 等待到完成

- **WHEN** 输入请求开始并成功写回
- **THEN** 立即显示翻译中且防重复请求，随后原位转换为目标语言和操作信息；不新增成功弹窗，不自动发送

#### Scenario: 请求结束或取消

- **WHEN** 成功、失败、超时、空结果或取消发生
- **THEN** 当前等待状态必定结束；取消保留草稿，旧请求的清理不得清除新请求状态

### Requirement: 输入翻译失败必须提供分级反馈

系统 SHALL 在本期支持的输入流程提供分级失败反馈，不得静默；固定目标语言同样显示成功条与失败反馈。

#### Scenario: 首次翻译失败与重试

- **当** 首次翻译发生网络、超时、限流、服务故障或未知错误
- **则** 必须保留原文，同位置显示「翻译失败」与「重试」，不显示语言选择或撤销
- **且** 重试沿用本次方向而不再次 enableCycle，期间显示「翻译中…」与原有输入框 spinner；成功才显示符合条件的纠错条，失败恢复 notice

#### Scenario: 不可重试的错误

- **当** 错误为内容安全拦截、未登录、套餐限制、额度耗尽或 BYOK 密钥鉴权失败
- **则** 必须仅提供明确说明而不显示重试或登录、升级按钮；已有成功译文的撤销仍可用
- **且** 内容安全说明为「内容未通过安全审核，无法翻译」，其余复用现有文案，不直接展示原始响应正文

#### Scenario: 首次失败后继续编辑

- **给定** 首次失败 notice 正在显示且没有重试请求执行中
- **当** 用户编辑原文、真正失焦、按 Esc 或发送消息
- **则** 必须关闭本次失败 notice；下一次按配置空格次数触发使用新的原文快照
- **但是** 重试 pending 的失焦仅隐藏，遵循请求结果暂存与原框聚焦恢复规则；失焦期间新到达的错误可在原框聚焦时展示
