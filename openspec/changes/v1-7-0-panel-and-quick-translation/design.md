# 1.7.0 面板与快捷翻译技术设计

## Context

采用用户选择的方案 A：在现有 fork UI、会话流程及上游翻译引擎上增量改造。已于 2026-11-10 完成需求确认和独立 architect-review 复审，结论为“审查通过，可以进入 propose 阶段”。本文件落实复审要求，不代表代码或平台验收完成。

现状证据：

- `src/fork/ui/popup/App.tsx` 是实际面板入口；`src/fork/ui/selection-content/input-translation/use-input-translation.ts` 承载输入会话、不可变原文、重译和旧请求守卫。
- `resolve-lang.ts` 当前解析 sourceCode/targetCode 引用，并可能使用聊天或网页语种；不能直接当作草稿自动识别。固定目标当前映射为 explicit，完成条部分路径会被过滤，必须解耦。
- `src/utils/constants/feature-providers.ts` 已定义各功能 providerId 的唯一字段；不能在 fork 再复制 providerId。
- 字幕 schema 没有独立语言，`universal-adapter.ts` 及 `translated-subtitles-downloader.ts` 读取全局语言，必须贯通真实执行及下载路径。
- `src/fork/config/storage.ts` 当前缺失配置只返回默认值，旧版读取会自行迁移；本次改为后台唯一升级入口。上游 `initializeConfig` 的 isFreshInstall 也包括损坏重建，不能当账号新老标记。
- `translateTextForInput` 仍重新读取全局 provider 和页面上下文；只传具体语言不能满足请求快照及限定聊天上下文契约。
- `FORK.md` 要求独立配置及最小接缝；上游引擎、schema、迁移不能为了本功能被复制重写。

## Goals / Non-Goals

目标：四功能配置独立且跨端一致；输入源识别草稿、目标用户设置；统一两次空格初始化并允许 2～5 次；六平台实际适配；面板设置联动、字幕范围、文字颜色和品牌入口可用。

非目标：统一重构全部翻译控制层、修改远端业务协议、实现文档翻译、无字幕识别、开放上游商业服务、自动发送消息、商店发布、冻结未审核视觉。备选方案 B 的统一控制层会扩大改动和回归范围，故不采用。

## Decisions

### D1：唯一配置归属

以下 fork 字段名为本次新增契约，不代表当前已有实现。所有持久更新经现有校验和补丁机制，不直接写未校验完整对象。

| 设置                           | 唯一来源                                                                                                                                          | 消费与升级                                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 网页语言                       | 主配置 `language.sourceCode/targetCode`                                                                                                           | 仍属网页；不得因其他功能操作修改                                                                     |
| 划词语言                       | fork `featureLanguages.selection`                                                                                                                 | 首次取主配置语言快照，此后独立                                                                       |
| 字幕语言                       | fork `featureLanguages.subtitles`                                                                                                                 | 同上；源自动时使用当前字幕轨语言                                                                     |
| 输入源                         | 当前草稿检测结果，仅请求内保存                                                                                                                    | 固定 auto-draft 语义；旧 fromLang 不再控制 fork 行为，无需向上游 schema 塞入 auto 枚举               |
| 输入目标                       | 主配置 `inputTranslation.toLang`，迁移后为具体语言码                                                                                              | 已有具体值保留；sourceCode/targetCode 引用转换为全局 targetCode 快照；此后禁止新写动态引用           |
| 触发次数                       | fork `inputTranslation.triggerCount`                                                                                                              | 整数 2～5，本次迁移为 2；后续保留                                                                    |
| 输入启用与间隔                 | 主配置 `inputTranslation.enabled/timeThreshold`                                                                                                   | 保留现有值，教程实时读取次数                                                                         |
| 轮换                           | 主配置 `inputTranslation.enableCycle`                                                                                                             | 升级写 false；fork UI 不暴露，执行忽略旧轮换，导入也规范化                                           |
| 提供商                         | 主配置 `pageTranslation.providerId`、`selectionToolbar.features.translate.providerId`、`inputTranslation.providerId`、`videoSubtitles.providerId` | 复用 `buildFeatureProviderPatch` 等，禁止 fork 镜像                                                  |
| 智能上下文                     | 主配置 `pageTranslation.enableAIContentAware`                                                                                                     | 网页与输入共享；有效能力同时受 provider 限制                                                         |
| 风格、模式、站点规则、字幕开关 | 各自已有主配置字段                                                                                                                                | 复用既有语义，不创建替代字段                                                                         |
| 网页样式预设                   | 主配置 `pageTranslation.translationNodeStyle`                                                                                                     | 保留 customCSS 与其他预设，不覆盖用户自定义样式                                                      |
| 最后选择的文字颜色             | fork `translationTextColor`                                                                                                                       | 因现有样式 schema 没有独立颜色槽，使用 fork 槽；通过既有样式更新机制投射到译文，未设置时沿用原有颜色 |
| 迁移版本与修订                 | fork schema 版本及功能配置 revision                                                                                                               | 区分协议版本与用户修改，不代表账户身份                                                               |

划词/字幕首次语言快照只在初始化或明确旧备份恢复时生成；正常读取不得反复跟随网页。不同存储键是同一配置模型的字段归属划分，不允许重复可写真源。

### D2：后台初始化、更新、备份和重置

在主配置初始化成功之后，`src/fork/background/` 的单一初始化入口启动 fork 迁移。所有消费端等待 ready；`loadForkConfig` 只读已初始化状态，不在多个页面独立迁移。新装和本次升级均使用相同规则，无账号/新老用户功能分支。

升级顺序：读取旧主/fork 快照并验证；计算新的 fork 数据与主配置最小补丁；保存恢复记录；提交数据并校验；最后提交完成版本并通知 ready。中断时先恢复或幂等续作，不释放半套配置。不以“没有 fork key”推断用户以前没有配置。

正常更新通过后台现有独立 fork 消息通道串行处理，接收字段 patch 与 expectedRevision，读取最新值后更新；冲突重读后重提，不无声覆盖整对象。主配置已有写入口需要通过字段合并及存储订阅纳入修订视图。消费端订阅主/fork 两个存储键，取得一致快照后刷新；配置改变令相关输入请求失效。

本地备份在 fork 包装层携带版本化的主配置和 fork 功能配置，兼容旧格式；不导出或恢复会话凭据、会员鉴权状态。完整新版备份保持有效用户次数；旧备份按导入的主配置重新生成缺失功能配置、次数 2，不混入导入前残留 fork 选择。导入全量校验后再写，失败使用恢复记录撤回。全重置同时重置主与 fork 功能字段，单功能重置只触及所选范围；旧的“仅主配置重置”UI 必须接入协调层，不能留下隐含两套状态。

回退优先使用实施前完整配置备份。新字段不改变上游 schema，但旧包不理解新行为；不能承诺直接装旧包即可保留新配置含义。

### D3：轻量功能配置解析与引擎接缝

新增 `src/fork/config/feature-config.ts`，只负责归一化与快照，不负责 UI 或统一任务调度。建议接口：

```ts
type TranslationFeature = 'page' | 'selection' | 'input' | 'subtitles'
// LanguageCode 复用项目已有类型；输入 source 在检测后才成为具体码。
type FeatureSnapshot = {
  feature: TranslationFeature
  source: LanguageCode | 'auto' | 'auto-draft'
  target: LanguageCode
  providerId: string
  revision: string
  contextEnabled: boolean
}
// 无副作用；读取者必须已越过初始化屏障。
resolveFeatureConfig(feature, mainConfig, forkConfig): FeatureSnapshot
```

实际 provider 通过现有 capability resolver 解析，执行前保留会员、额度及权限校验。输入 fork executor 将检测出的具体语言、稳定 provider、限定上下文传入公开 `translateTextCore`；复用其缓存、术语、hostedFeature、换行保留和错误路径，不复制引擎。不能直接继续调用会重读全局 provider/网页摘要的旧 `translateTextForInput` 而声称已有快照隔离。先做调用影响分析，若公开接口无法保持必要能力，仅引入有边界登记的最小可选参数接缝，默认行为保持兼容。

划词及字幕在现有调用位置消费同类快照。字幕翻译、缓存、下载、文件名/语言标签及后台事件必须使用实际结果元数据；不得下载时读取最新全局语言替换旧结果语言。缓存语言对、提供商和影响结果的提示词/上下文均遵循现有隔离机制；不修改全局配置制造语言切换。

### D4：输入请求状态与源语言检测

延续原 hook 的输入元素、不可变 originalText、请求身份、会话标识和显示状态分离。逻辑状态为 idle、detecting、translating、success、error；detecting/translating 均显示“翻译中”。请求开始即创建守卫并显示等待，不等识别结束才显示。

检测仅取触发序列前的当前草稿，用现有本地检测能力评估可识别结果；不依赖整页存储语言或聊天语种。输入过短、全表情等无法可靠识别时保留原文，显示“无法识别输入语言，请补充内容后重试”，退出 pending，不请求翻译。识别出的语言与目标相同沿用同语言提示，不发请求。

成功完成条不再依赖 chatContext/pageSource 来源：保存目标显示“已设置”，临时重译显示“手动选择”。临时改语言始终用最初原文，不隐式修改持久目标；撤销保留原始空白。请求期间编辑使旧结果失效，成功后编辑仍保留撤销快照，不能混淆两个时段。失焦隐藏/重新聚焦恢复、分层 Esc、真实发送清理沿用既有完整场景。

网络/超时/服务故障允许重试；登录、额度、内容审核等复用 `input-translation-error.ts`，不显示原始响应。失败、空结果、取消均退出等待；取消不写输入。任何晚到结果和 finally 都只能清理自己的请求，不能清掉新请求。重复触发、IME 组合输入、间隔断开、非空格插入均按完整触发序列测试。

### D5：六平台适配与上下文边界

复用 Discord 与 Telegram 已有实现，对 YouTube、X、WhatsApp、Reddit 补当前编辑器适配。每个适配器提供编辑器判定、所属对话/帖子标识、上下文提取、提交/卸载信号与安全写回。选择器必须来自真实页面证据，不能按原型虚构。

AI 上下文只取所属会话的可见相关消息或帖子，清理时间戳、用户名、引用噪音；不扫描所有页面输入框。无法取得上下文时允许无上下文翻译，目标语言始终用户指定。普通提供商不提取/提交模型上下文。六平台模块显示不能代替功能准入；分别覆盖聊天、评论/回复及发帖中实际适用的编辑器，并记录不适用或未验收场景。

### D6：面板、设置与提供商

面板状态仅保存当前打开功能和焦点，不保存第二套业务配置。关闭按钮、外部点击和 Esc 返回首页，配置保留；全部设置复用现有路由并选中对应导航，不发明重复设置页。原型版本切换属于评审工具，正式扩展按构建发行版，不新增运行时切版开关。

网页主操作连接真实请求状态，禁止重复提交，完成可恢复原文；站点禁用使内容端操作及在途结果失效，恢复保留配置。账户入口沿用现有账户/用量；海外兑换、翻译中心使用现有真实地址；文档地址未就绪显示未开放，不使用原型相对 URL。

统一 selector 目录供面板和完整设置使用。普通翻译 Google/Microsoft；托管目录按发行版过滤，既有会员/能力门禁继续生效。原型的模型名称、顺序、倍率作为核对清单，不复制静态示例冒充服务配置；目录缺项需记录并阻止相应验收，不替用户偷偷换收费模型。空态、无额度、不可用服务、浏览器限制页均复用错误分类。既有自定义风格和自定义动作可继续从完整设置访问。

### D7：字幕、划词品牌与颜色

字幕通过现有 YouTube/X/Netflix adapter 和 fork 准入路径实现，只翻译已有轨道。功能开关控制入口/处理，播放器开关只控制译文显示。语言快照覆盖全文轨、分段流、重试及下载路径，避免仅改变面板。

划词品牌入口调用当前选区翻译，保留朗读及键盘操作，不打开 popup。等待和完成状态保留正式品牌标识，不以 spinner 取代。已有正式资源优先，最终视觉资源后补。

文字颜色面板只在文字颜色预设出现；fork 颜色槽通过既有样式通知/渲染入口更新已显示译文和预览，禁止发翻译请求；关闭选择器未修改不写值。切换预设隐藏控件但保留颜色，customCSS 保持独立。没有批准色板或新默认色时沿用现状，仅提供现有可用选色交互。

## Risks / Trade-offs

- 图索引：已知数据库存储版本 43、当前引擎 42，调用风险未解析。实施首项为恢复兼容并对目标符号 impact；HIGH/CRITICAL 必须先告知用户，UNKNOWN 需补充证据，不能以本设计审查豁免。
- 主/fork 跨键写入：后台串行更新、恢复记录与 ready 屏障；失败不得开放混合配置。备份与重置必须覆盖两个存储来源。
- 旧规格冲突：本次 delta 删除聊天决定语言及网页回退要求；保留会话、撤销、焦点和同语言提示等既有行为，并扩展固定目标完成条。
- 平台 DOM 漂移：真实页面证据与会话级 guard；模型上下文不可被聊天语种检测选择器冒充。未验收平台明确列出，不能报告全部通过。
- 上游同步：使用公开引擎/组件及最小 fork 接缝，按 `FORK.md` 登记必须修改的边界；不得直接刷新漂移指纹压过失败。
- UI 未定稿：当前仅功能验收，后续视觉任务单独补充，不以本方案中的现有组件效果作为最终设计。

## 验证与文件落点

技术栈沿用 TypeScript、React、Jotai、WXT、Zod、Vitest。计划文件落点见 tasks.md；新增路径均为计划，实施前必须用图分析确认现有调用接缝。关键断言覆盖：两次初始化只一次、用户后改次数保留、旧备份导入、独立语言跨端传播、固定目标显示完成条、检测期间切会话不发请求、撤销恢复原始空白、上下文不跨会话、字幕下载语言一致、颜色变更零翻译请求。

PowerShell 本地测试先设置 `$env:SKIP_FREE_API='true'`；主与 fork 套件分别验证，free-api.test.ts 有意跳过。类型检查、格式检查、双版构建、边界与品牌检查及真实平台验收在 tasks.md 明确分列，不将单测视为实站验收。
