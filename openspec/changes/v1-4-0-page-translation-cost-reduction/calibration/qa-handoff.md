| 类型                | 现有证据                                              | 测试需准备/补验                                          |
| ------------------- | ----------------------------------------------------- | -------------------------------------------------------- |

| OpenAI / Responses  | 缺少直接服务配置                                      | 正确 endpoint、模型、适配器；分别确认实际采用的 API 路径 |

| Qwen / GLM 兼容服务 | 已测网关别名不等于独立兼容接口                        | 独立兼容 endpoint 与模型，验证请求/响应契约              |
| 弱模型 / 本地模型   | 未配置                                                | 可复现的弱模型或本地服务，包含结构化输出不稳定场景       |

密钥只填入受控测试配置，禁止写进聊天、文档、截图或提交 HAR。导出证据必须去除 Authorization、Cookie、会员标识等敏感数据；保留模型、参数、脱敏请求内容、响应结构、时序和 usage 即可。

每类都需验证：

1. 默认提示 flat JSON 的 t0… 对应正确，不漏项/错位；HTML numeric marker 可完整恢复。覆盖嵌套标签、链接、代码、中文/emoji、换行、自闭合标签、同文不同上下文。
2. 自定义提示及其他内置模板仍走原协议，字幕/输入翻译等非页面调用不改变行为。
3. 部分字段缺失、空值、重复/未知键、格式损坏：仅失败项最多单次降级，成功项不重发，不发生队列死锁；保留实际每次尝试和 usage。
4. 使用可控测试服务安全模拟 401/429、网络失败、超时迟返回、取消；不得故意压测生产服务制造限流。认证/限流/取消不误触发协议降级，真实请求结束前不提前释放槽位。
5. 双标签页、翻译中关闭/重开页面翻译、切换配置/语言/provider、取消后迟响应：不串结果、不污染取消后的缓存。

当前 Prime-Astra 首次超时的 usage 未知，成功重试的输入 usage 较其他别名高，需重点检查完整账单口径；不可把超时按零消耗。

## B. 固定数据与真实降本（对应 5.1、5.2）

固定三页：Wikipedia Machine translation、React Thinking in React、MDN Functions。已有 [manifest](manifest.json) 与实际引擎取文 JSON 可作初始样本；若重新取文，保存新的 hash，不覆盖旧证据。

1. 每个对照明确插件构建 hash、浏览器/OS、时间、provider/模型/endpoint、语言、双语/译文模式、preload、缓存状态和 tokenizer。每页每次使用独立冷缓存测试环境，并另测暖缓存，禁止混算。
2. 旧实现/旧协议 4/1000 与新实现 4/1000、8/2000、16/4000 使用同一取文输入；同批参数需多次运行，至少覆盖上述三档。区分协议收益与增大批量收益。
3. 统计首发、重试、失败项降级的所有调用；逐次保存实际 prompt/input、completion/output、reasoning、cache usage 及失败状态。usage 缺失列为未知并设法从服务侧账单核对；未补齐前不能宣布完整成本达标。
4. 输入 token 降幅按同模型同口径旧值计算，门槛候选≥50%；同时分别报告总 token 和计费成本，不把输入降幅当总账单降幅。本地 o200k_base 估算仅辅助解释。
5. 对照原文检查漏译、错位、语义、marker/链接/排版及失败率，不以 HTTP 200 或含中文作为质量通过的充分条件。

16/4000 边界已覆盖，测试可直接回归：16/17 项、准备后 3999/4000/4001 字符、单个超长片段完整独立发送。数值以准备后的 `.length` 为准；JSON 键和提示不在 4000 字符之内，缓存/到达时间会使实际批次小于上限，不要求每批填满。

## C. 免费线路与请求数量（对应 5.1、5.2）

- Google/MS 已完成 100/101 项及非 ASCII/转义后的载荷分批。还需覆盖恰好载荷边界、单项超载的独立调用、部分失败、换行/实体解码及 HTML 禁用回归。
- 三页真实滚动 Google 已记录 12+23+16=51 次尝试，包含 3 次失败尝试。设计写的是“三页≤30请求”，按合计目前未达，不可改读为“每页≤30”。测试需在冻结同口径的旧/新构建下重测；如仍不达，研发分析批量到达时序、重试等实际原因，若需修改目标须产品另行确认。
- 同口径记录旧/新首次请求数及全部尝试数，单独计算首次请求降幅≥90%是否达到；不能用原文片段数冒充旧版实际请求数。
- Google 曾有 100 项及 1 项控制组的短暂网络错误，后续同 100 项成功。继续观察跨网络/时段失败率；不能归结为确定的 100 项上限错误，也不能说网络问题已修复。

## D. 浏览器性能与交互（对应 5.3）

已有 React + Google + headless Chrome 新实现并发 2/4/6 各三次；首段 median 348.1/350.8/354.0 ms，合成点击输入约 213/214/211 ms。未有旧版对照，并发 6 未饱和，不能直接用于发布定档。

补验步骤：

1. 相同机器、页面快照、缓存、网络及扩展集合，准备可验证 hash 的旧版基线和新候选；并发 2/4/6 交错运行，每档至少三次，记录原始值和 median，不挑最佳值。
2. 三页各测 Google、Microsoft、代表性 LLM；包含慢响应/足够片段使上限确实饱和的受控场景，测到真实在途请求数，而不只是配置字段。
3. 首段译文 median 对旧版≤+20%；记录总耗时但不以其单独替代首结果验收。
4. 有界面 Chrome、Edge、Firefox 实际滚动、点击业务控件、输入翻译、前置摘要、划词浮层；页面请求饱和时也能响应。保存录像/性能 trace 和操作→结果延迟，不能以附加测试控件代替业务功能验收。
5. 记录 >50 ms long task、帧间隔、主线程占用；将页面自身任务与扩展影响区分，判断交互不退化。

## E. 版本、迁移与回滚（对应 5.4）

- 先完成以上验收，产品/研发依据质量、完整成本和体验确定默认值，不能只看理论 token 最低。
- 在独立测试 profile 验证新装、旧包升级、精确旧值 4/1000、自定义组合、重复启动、迁移写失败恢复；不得覆盖用户自定义设置。当前已有自动化覆盖，但仍需真实升级链路证据。
- 最终设置 fork-version 1.4.0，并以该版本重新构建/回归 Chrome、Edge、Firefox；不修改上游版本或擅自执行发布。
- 演练回滚到已知可用配置/构建，验证数据兼容性、翻译可用和自定义配置保留；证据齐全再勾选 5.4。提交、推送、归档、发布另按授权执行。
