# 2026-09-12 补充实测报告

## 结论与验收边界

本轮补齐了三页真实取文、LLM/MT 批量边界、四个新增网关模型冒烟、页面饱和时输入队列隔离，以及 React 页面并发 2/4/6 各三次的浏览器观察。业务代码、用户持久配置及生产构建未改动。

这些结果支持继续验证候选 **16/4000、页面并发 4**，但不构成全量发布验收：原生模型接口、三档真实 LLM usage 对比、旧版本同口径性能基线和部分真实交互仍缺失。Google 三页实际共 51 次翻译请求，尚未达到设计中“三页≤30请求”的合计目标；也没有同口径旧版数据证明降低≥90%。OpenSpec 仍为 10/14，5.1–5.4 保持未完成。

用户已明确：当前不能提供其余模型配置，不能验的项目交测试团队配置补验。具体见 [测试交接清单](qa-handoff.md)，此安排不是缩减原验收范围，也不代表已经向外部团队发送。

## 1. 16/4000 的真实请求边界

模型：任译喵网关 `GLM-5.3-Flash (0.32x)`，默认 JSON 协议。证据：[live-results.json](evidence/live-results.json)，对应名称 `llm-count-*`、`llm-exact-*`、`llm-single-4001`。

“16/4000”指单批最多 16 个片段、准备后的片段文本 `.length` 合计最多 4000；不是 4000 token，也不是整个 HTTP body 4000 字节。准备阶段会去除不可见字符并 trim；默认 JSON 的键、提示和请求封装不计入该字符合计。当前 `.length` 是 JavaScript UTF-16 长度，emoji 等不应按肉眼字符数推算。

| 输入                  | 实际首次分批            | 结果                     |
| --------------------- | ----------------------- | ------------------------ |
| 16 个短片段、438 字符 | 16 项/438 字符          | 16/16 成功               |
| 17 个短片段、466 字符 | 16 项/438 + 1 项/28     | 17/17 成功               |
| 两片段合计 3999 字符  | 2 项/3999               | 2/2 成功                 |
| 两片段合计 4000 字符  | 2 项/4000               | 2/2 成功                 |
| 两片段合计 4001 字符  | 1 项/2000 + 1 项/2001   | 2/2 成功                 |
| 单片段 4001 字符      | 单独一项/4001，完整发送 | 1/1 返回成功，约 74.3 秒 |

单片段超过上限时单独发送，不为凑 4000 而截断原文；这类单项请求不能直接判为分批违规。最后一项只验证完整发送和有结果，不代表长重复文本的语义质量已经验收。

最初 `llm-chars-3999/4000/4001` 使用空格补齐，trim 后实际分别为 3998/3998/4000，因此不是精确边界证据。原记录和消耗全部保留，随后用非空白结尾重跑 `llm-exact-*`，以上表格采用修正后的测试。

## 2. Google / Microsoft 批量与载荷边界

| 场景                        | Google                                     | Microsoft                             |
| --------------------------- | ------------------------------------------ | ------------------------------------- |
| 100 个短片段                | 复测一次请求、100/100 成功，body 3114 B    | 一次请求、100/100 成功，3091 B        |
| 101 个短片段                | 分成 100+1，101/101 成功                   | 分成 100+1，101/101 成功              |
| 64 个含 `é`、`&` 的较长片段 | 分成 34+30，body 31430/27744 B，64/64 成功 | 分成 34+30，31407/27721 B，64/64 成功 |

载荷用 UTF-8 编码后的实际 body 字节判断，而不是原文字符数。测试中实体转义也会增大文本长度。候选策略为 32 KiB 总预算并预留 512 B 封装，以上观察均在总预算内；这不是对所有边界字符串的穷举证明。

必须保留的失败：Google 最初 100 项的三次尝试均为 network-error，随后 1 项控制组也连续三次 network-error，32 项控制组成功；稍后对相同 100 项载荷复测成功，101 项也成功。因此不能将早先失败归因为“Google 不支持 100 项”，也不能说外部连接故障已解决。根因未进一步定位，测试需保留失败率/重试观察。

### 页面饱和时输入队列

Microsoft 601 个页面片段分成 7 批，601/601 成功，约 5.08 秒完成。在观测到 4 个页面请求在途时，经真实 `enqueueTranslateRequest` 消息提交 `hostedFeature: inputTranslation`，输入请求在页面请求未结束时发出，约 216 ms 返回。

这是运行期队列隔离证据；不是实际输入框翻译 UI、前置摘要或划词浮层的端到端交互验收。

## 3. 新增四个网关模型冒烟与实际 usage

同一组 4 个 MDN 正文片段，共 834 字符；均返回 4 项可用译文。逐项阅读样本，function、square、number 等核心含义保留；不代表全页质量或 marker 契约已经覆盖。

| 网关别名                    | 尝试次数 | 总耗时   | 已知 prompt_tokens | 已知 total_tokens |
| --------------------------- | -------- | -------- | ------------------ | ----------------- |
| DeepSeek-V4.1-Flash (1.20x) | 1        | 3954 ms  | 462                | 1100              |
| Kimi-K2.7 (2.60x)           | 1        | 5194 ms  | 421                | 973               |
| MiniMax-M3 (1.84x)          | 1        | 4311 ms  | 573                | 1095              |
| Prime-Astra (4.00x)         | 2        | 43666 ms | 5095               | 5298              |

Prime 首次约 32.5 秒超时，没有返回 usage；表内只包含成功重试的 usage，不能视为完整成本。相同输入在该网关别名上报告的 prompt_tokens 显著较高，原因未确认，不可推测为某种计费或隐藏提示机制，也不可用本地 tokenizer 替代其实际口径。

结合之前 GLM/Qwen，已有六个网关模型别名样本，但它们仍共用网关接口，**不等于六类 API 适配器验收**。原生 OpenAI/Responses、Anthropic、Gemini、独立兼容服务及弱/本地模型待测试配置。

本文件 `live-results.json` 共 23 个场景、41 次网络尝试，其中 7 次失败尝试：Google 6 次、Prime 1 次。LLM 16 次尝试中 15 次有 usage；已知输入合计 **13988**、已知总 token **32322**，均为下界，缺失 usage 的尝试不能按零计。该合计包括初始无效边界构造的消耗，不包括此前报告或本轮三页/矩阵的免费请求。

## 6. 页面并发 2/4/6 矩阵

React 真实页面、Google 线路，每档三次，按 2→4→6 的顺序交错重复，每次全新 profile。三个临时构建副本只替换唯一的页面 `maxConcurrent` 默认数字；生产 `.output/chrome-mv3/background.js` SHA-256 前后相同：`77bed37758ffd86b4ac74c7b70dfbc3bfa537659a4736255f63b260baac98d0b`。副本 hash 见 [matrix-variants.json](evidence/matrix-variants.json)。

| 并发候选 | 首段中文 median | 点击+输入探针 median | 三次网络尝试数 | 观测最大在途 | long task >50 ms |
| -------- | --------------- | -------------------- | -------------- | ------------ | ---------------- |
| 2        | 348.1 ms        | 213 ms               | 24 / 24 / 23   | 2            | 均为 0           |
| 4        | 350.8 ms        | 214 ms               | 22 / 26 / 25   | 3            | 均为 0           |
| 6        | 354.0 ms        | 211 ms               | 28 / 26 / 27   | 3            | 均为 0           |

首段值从启用翻译前安装探针起，到译文 wrapper 中首次出现中文；点击+输入值为 Playwright 实际点击附加按钮并输入 hello 的墙钟耗时，包含自动化开销。九次均点击一次且录入 hello，最终 spinner 为零。另记录 rAF 帧间隔，部分运行存在一次 >50 ms 间隔，不应表述为“完全没有掉帧”。

局限：探针控件是附加到真实页面的 `translate=false` 测试控件，不是 React 业务表单；滚动为程序驱动；没有划词翻译 UI 或 LLM 页面性能。每次取文 206–229 项、12710–13253 字符，页面/翻译布局到达时序导致工作量不同，不能当成完全相同快照。并发 6 实际只达到 3，没有充分饱和；当前负载下未看到它的明确收益，不代表所有页面都无收益。

此处比较的是同一新实现的不同并发参数，不是旧版基线。“首结果≤旧版+20%”和交互不退化的发布门仍待验，不能现在冻结默认值。

## 7. 复现、回归与环境恢复

- `used-collect.mjs` 为最终矩阵采集脚本；初始三页版本没有附加点击/输入/rAF 探针。该脚本会在隔离 profile 写入测试配置，不能直接移植为操作日常用户 profile 的脚本。
- `used-matrix.mjs` 创建临时构建副本并调用采集脚本；`used-token-analysis.mjs` 是静态估算；`used-server.mjs` 是本地证据收集服务，不是完整的线上边界用例执行器。
- 这些文件是本机实际使用脚本存档，保留了绝对 runtime、仓库和临时路径，**不是开箱即用的通用测试工具**。重跑需先调整路径/文件名和依赖，重新构建并核对 hash；不可把临时副本当发布包。
- `evidence/*.json` 保留原始字节以匹配 manifest，四份 `used-*.mjs` 保留当时脚本内容；根 oxfmt/oxlint 配置仅对本目录这些存档设置检查排除。方案文档、业务源码与测试继续正常检查；重跑产生新证据时须重新核验 manifest 的字节数与 SHA-256。
- 本轮追加回归：`SKIP_FREE_API=true pnpm run test src/fork/page-translation/__tests__ src/utils/request/__tests__/request-queue.test.ts`，9 文件、95 测试通过（2026-09-12 20:45）。本轮未重跑全量测试/三浏览器构建；此前结果见 [validation.md](../validation.md)。
- 用户 Chrome 中临时 fetch 包装已恢复、消息观察器已移除、`__v140*` 全局已清理；未清除用户翻译缓存，保留其原 DevTools Network 记录和会员登录。测试只使用独立命名的缓存键。
