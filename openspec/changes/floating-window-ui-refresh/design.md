## Context

悬浮窗由 fork 的 `src/fork/ui/side-content/floating-button/index.tsx` 及 `hidden-button.tsx` 提供展示，复用现有翻译按钮、消息总线和配置存储。用户要求仅改 UI，反馈入口不展示。

## Goals / Non-Goals

**Goals:** 按指定设计更新悬浮窗展示；保持现有行为；验证真实扩展中的视觉和交互。

**Non-Goals:** 不改翻译、侧栏、权限、网络请求、持久化结构和共享反馈能力；不增加反馈入口、配置项、依赖或通用抽象；本任务不含提交推送、发布和归档。

## Decisions

### D1: 沿用现有行为边界

只调整 fork 悬浮窗展示组件与必要资源、测试。`FloatingButton` 继续拥有局部展开、菜单、拖拽状态；配置继续通过 `configFieldsAtomMap.floatingButton` 读写。保留 `clickAction` 的翻译与侧栏分支、翻译按钮、设置消息、站点禁用、全局禁用、锁定、键盘触发、全屏取消拖拽和 Firefox 侧栏提示。不为视觉更新新增状态层。

### D2: 最小资源与适配边界

复用现有翻译组件与隐藏按钮适配；必要展示参数只用于当前悬浮窗，不重写翻译行为。反馈入口移除后仅清理悬浮窗专用且无消费者的处理函数及导入。共享反馈工具保持不变。新增用户可见变更的 changeset。

翻译组件通过可选 `icon` 展示参数接入 fork 资源，未传参数时保留上游默认图标；消息与状态逻辑不变。该单一上游文件和本变更 changeset 在 fork allowlist 精确登记，不扩大目录级白名单。

## Risks / Trade-offs

- 展示结构影响拖拽几何计算：保留现有动态测量，真实浏览器验证释放位置、两侧贴边、悬停命中区域、菜单保持展开。
- 素材来源不完整：先读取正式导出边界及节点属性；无法核实的资源不得凭截图猜造，阻塞时明确记录未完成项。
- 旧外观断言需更新，但不得删除行为回归以让测试通过。
- 回滚只撤销本变更展示及资源改动，不改配置数据。
