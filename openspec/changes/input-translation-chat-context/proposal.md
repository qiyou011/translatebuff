## Why

「输入翻译」的目标语言选「网页源语言」时，在 Discord 上恒定翻成英文——Discord 的整页语言等于它的界面语言（`<html lang="en-US">` 加全英文 UI 框架），与频道里正在聊的语种无关。在随时切换语种的国际化社区，这个选项等于不可用。

竞品（沉浸式翻译）改为跟随**当前对话**的语言：实测同一频道内韩语消息在前、日语消息在后，它选了日语。

目标：在声明了聊天上下文的站点上，让「网页源语言」跟随对话语言；并给用户一个当场纠错的手段。

2026-09-05 真机检查发现：Discord 深色页面上的内联条显示黑色语言名称，展开菜单仍为白底。内联条背景与扩展主题文字混用，导致可读性与宿主风格不一致。本次补充输入区域主题适配方案（用户已确认，待实施）。

## What Changes

- 新增一份「站点 → 对话消息选择器」的登记，声明哪些节点是对话消息。Discord 填入其消息选择器；其余站点未登记，行为不变。刻意不做成站点规则的新字段——那要动 `src/types/config/` 下的 zod schema（绝不改区），fork 在上游合并前会永远带不了这份数据。噪音排除项仍取站点规则已有的 `excludeSelector`。
- 输入翻译的语言解析从翻译引擎**上提到调用层**（`use-input-translation.ts`）。引擎 `translateTextForInput` 签名与实现零改动。
- 解析规则：目标语言为「网页源语言」**且**全局源语言为「自动」**且**站点已登记对话选择器时，取最近 5 条消息判定语言；判不出则回退整页源语言。全局源语言被用户钉死为具体语种时**不启用**，不覆盖用户的显式选择。
- 输入框上方新增内联条：`翻译为 [语言 ▾] ｜ 自动检测 / 按网页源语言 / 手动选择 ｜ 撤销`，可手动改语言并拿原文重译，改完标注转为「手动选择」。翻译成功后保存触发前三空格时的原文快照；用户随后删除、修改或新增译文内容，内联条继续保留，点击撤销仍恢复这份原文，而不是任何编辑后的中间状态。焦点真正离开输入框及内联条交互范围时只暂时隐藏，重新聚焦同一输入框后恢复；消息实际发送、用户按 Esc、点击撤销或输入元素卸载时才永久结束会话。语言菜单展开时第一次 Esc 仅关闭菜单。语言由配置直接给定（源语言被钉死、固定语言码）时不挂条子——没有自动判定，也就没有要纠错的对象。
- 解析出的语言等于目标语言时不再静默：在输入框上方、与内联条同一位置挂一条同款提示「与目标语言相同，未翻译」，不带撤销按钮（那次什么都没换）。
- 内联条、同语言提示与语言菜单统一跟随输入区域深浅色主题。Discord 优先使用实测确认的主题标记，其他页面通过有效背景色判断，无法可靠判断时回退扩展主题；采用稳定不透明底色保证文字对比度，主题切换不得重置翻译会话。
- 语言菜单使用输入翻译专属的 Portal 容器承接局部主题，向上展开、受可用空间约束并内部滚动；常规宽度约 220–320px，窄视口优先保证菜单不溢出。

## Capabilities

### New Capabilities

- `input-translation-chat-context`: 输入翻译在声明了聊天上下文的站点上，按最近若干条消息判定目标语言，并提供内联的语言纠正与撤销入口。

### Modified Capabilities

无。本次不改动任何既有 Spec 的需求。

## Impact

- **配置**：不新增配置项，不改 `configSchema`，不需要迁移。「网页源语言」在已登记对话选择器的站点上语义收窄为「当前对话语言」。
- **站点规则**：不修改 schema、`resolve.ts` 或 `built-in/rules.json`；fork 内维护独立消息选择器登记，只复用上游已有的噪音排除规则。
- **调用层**：`use-input-translation.ts` 在 `enableCycle` 互换之后、调用引擎之前插入解析；新增内联条组件与状态。
- **翻译引擎**：`translate-variants.ts` 不改动。
- **局部主题与菜单**：输入翻译实现与测试集中于 `src/fork/ui/selection-content/input-translation/`；专用语言选择器负责 Portal 与定位，复用上游未修改的语言数据、输入和列表组件。恢复两个共享 Combobox 文件，不改变整个 selection Shadow Root 的主题或用户主题设置。
- **缓存**：`extraHashTags` 由 `inputTranslation:sourceCode->targetCode` 变为解析后的具体语种对，缓存分片变细、旧条目失效；不会脏命中，因哈希本就包含解析后的源/目标语种。
- **交付路径**：2026-09-05 用户确认优先 fork 自持，以降低不定期同步上游的文本冲突。fork App 直接挂载唯一的 fork hook，恢复上游 hook/index；以指纹哨兵提醒人工移植上游修复。历史上游 PR 拆分方案保留溯源，不作为当前实施前提。
