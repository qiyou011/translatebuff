## ADDED Requirements

### Requirement: 三类上游云服务统一禁用

系统 SHALL 在国内、海外的开发、测试、正式构建中，阻止上游功能链路对 `/api/identity`、`/api/rpc`、`/api/blog` 前缀本身及其子路径发起网络请求。禁用不得依赖上游域名或用户手动开关，也不得改写自有环境变量为无效地址。

#### Scenario: 不同发行版与环境采用相同策略

- **WHEN** 任一发行版和环境启动扩展并使用上游账号、云服务或博客相关代码路径
- **THEN** 三类服务均在本地结束，真实 fetch 和 backgroundFetch 出口均无对应网络请求

#### Scenario: 不误伤用户指定的外部服务

- **WHEN** 普通网页或用户自配 provider 使用与被禁用端点相同的路径名称
- **THEN** 系统不按浏览器全局路径黑名单阻断该请求，禁用仅作用于上游云功能边界

### Requirement: 云功能界面与后台触发停止

系统 SHALL 隐藏上游账号、托管 AI 配额、云转录、Notebase 云保存及博客通知入口，停止相关查询和后台业务触发，并保留已有调用需要的消息及模块导出契约。

#### Scenario: 扩展页面不启动云查询

- **WHEN** 用户打开弹窗、设置页、划词界面和相关引导
- **THEN** 不显示或推荐上述不可用云功能，不挂载其请求，不出现持续 loading 或上游登录/购买诱导

#### Scenario: 后台重启与会话变化

- **WHEN** 扩展冷启动、Service Worker 重启或认证 Cookie 变化，且存在旧 Notebase 待保存任务
- **THEN** 不运行云笔记保存任务、不请求上游身份或 RPC，且不删除待保存数据

#### Scenario: 托管 AI 状态消息保持可响应

- **WHEN** 调用方发送 getHostedAiStatus 消息，或代理层调用状态缓存清理导出
- **THEN** 调用正常完成；状态消息返回 null，不读取旧可用状态、不请求服务器、不发生处理器或导出缺失错误

### Requirement: 意外云调用明确终止

系统 SHALL 对仍然触达的上游 RPC 和不支持的认证操作返回可识别的禁用结果，不模拟业务成功、不回退到原上游客户端，且不得因该结果自动重复调用、轮询或持续显示加载状态。博客查询 SHALL 按既有契约返回 null。

#### Scenario: 绕过运行时兼容直接触发普通或流式 RPC

- **WHEN** 调用绕过请求前兼容边界进入任一上游 RPC 客户端，包括流式请求
- **THEN** 请求在本地被拒绝，调用流程结束，不联网、不伪造译文或云保存成功、不自动重试或回退到上游；请求前解析到合格 local provider 的正常调用不属于该禁用失败路径

#### Scenario: 禁用与正常任务并存

- **WHEN** 同一队列存在禁用调用与使用有效非上游 provider 的正常翻译
- **THEN** 禁用使用独立错误语义及既有不可重试标记，不借用账号、额度或 access-denied/401/403/404 错误触发共享队列失败；正常任务不被连带终止，禁用流程不持续加载

#### Scenario: 流式端口只保留错误文本

- **WHEN** 前端准备执行禁用模型请求，且后续端口不保留结构化错误元数据
- **THEN** 前端在请求前结束禁用路径，不依赖端口传回不可重试标记才能终止，不修改全局重试规则或消息协议

#### Scenario: 博客直接调用或旧缓存存在

- **WHEN** 代码直接调用 getLatestBlogDate，或者用户打开含旧博客缓存的界面
- **THEN** 查询返回 null 且不联网，界面不因旧缓存重新显示更新提示，其他纯工具功能保持不变

### Requirement: 上游翻译核心与自有业务保留

系统 SHALL 保留上游翻译核心、当前支持的非上游 provider 路径、任译喵登录会员网关及自有特性，隔离上游云能力不应改变这些路径的域名、请求协议或独立状态；不以本变更扩大当前隐藏模型的 UI 支持范围。

#### Scenario: 自有登录与模型服务继续运行

- **WHEN** 用户恢复任译喵会话、查询会员额度、发起网关翻译、打开官网或执行登出
- **THEN** 行为与改造前一致，上游无会话状态不清除自有凭据、不改变自有接口地址

#### Scenario: 翻译功能回归

- **WHEN** 用户使用自配 provider、页面翻译、划词翻译、普通字幕提取及翻译，或 Discord 输入翻译
- **THEN** 这些不依赖上游云服务的路径继续工作；Discord 三空格触发、修改译文后撤销回原文、失焦再聚焦和语言菜单搜索行为保持不变

#### Scenario: 字幕高级处理与云转录区分

- **WHEN** 用户提取并翻译已有字幕，或使用字幕摘要/分段
- **THEN** 前者继续运行，后者依照所选模型的 LLM 能力执行；不要求纯翻译器生成摘要，不因上游云转录禁用而关闭普通字幕功能

#### Scenario: 自定义动作与笔记功能区分

- **WHEN** 用户使用自定义动作或内置词典，或打开当前 fork 划词界面
- **THEN** 合格非上游模型的生成能力保留，Notebase 云保存不可用；当前已移除的笔记建议入口与生成调用不得因兼容逻辑而恢复

### Requirement: 旧上游模型在运行时兼容且不新增配置迁移

系统 SHALL 在页面、划词、输入、字幕翻译及自定义动作构造请求前，将旧 system provider 引用临时解析到现有配置中首个启用、能力匹配且满足现有凭据门控条件的任译喵 provider；有效 local 解析结果 MUST 保持不变。无合格候选 SHALL 在业务请求前结束并引导登录或选择模型，不新建 provider、不请求上游、不自动重试、不回退到任意其他收费服务。语言检测和当前关闭的笔记建议 MUST 排除在此自动替代规则外。

#### Scenario: 不依赖打开设置完成旧配置兼容

- **WHEN** 扩展冷启动或恢复旧配置，用户未打开弹窗、设置或重新登录，翻译配置引用 system 且已有合格候选
- **THEN** 按配置顺序解析为真实 local provider 再构造请求，使用既有服务和额度规则；兼容不依赖 UI 挂载或新增持久化迁移

#### Scenario: 显式旧快照与无合格候选

- **WHEN** 调用方直接传入 system 快照绕过常规解析，或现有候选缺 key、被禁用、不支持该能力
- **THEN** 显式快照仍按同一规则在请求前处理；没有合格候选时给出可操作提示，不查询 hosted 状态、不进入生成/重试，不伪装为翻译成功

#### Scenario: 实际执行模型与参数缓存一致

- **WHEN** 持久化选择仍为上游模型，但本次已解析为任译喵 local provider
- **THEN** 提示词、模型参数、温度、缓存标识、统计和执行模型展示使用最终 local provider，不复用旧 hosted 身份缓存，不为修正展示写回持久化选择

#### Scenario: 不改变现有配置和会员同步职责

- **WHEN** 运行时做兼容决策，或既有种子、登录及凭据同步流程正常执行
- **THEN** 新兼容逻辑不新增配置写入或批量重指向，既有同步行为保持不变；同步解析器不读 storage、不做网络/会员刷新或 SDK 初始化，必要的异步流程仍在原边界执行

#### Scenario: 候选凭据不等于服务端权益确认

- **WHEN** 候选满足本地 key 条件，但凭据已过期或实际额度不足
- **THEN** 使用现有凭据/权限/额度处理，不将 key 非空当成有效会员证明，不新增权益判断体系或更换付费服务；有效的非上游模型配置不被新兼容逻辑替换

### Requirement: 语言检测在生成前降级本地

系统 SHALL 保留本地语言检测和有效非上游 LLM 检测路径；对于显式 system ref，或未传 ref 且当前配置为 system 的检测调用，MUST 在生成请求及原有尝试循环之前降级本地检测，不自动选择付费模型、不写回配置。显式有效 local ref SHALL 优先于持久化 system 配置。

#### Scenario: 常规检测入口使用本地算法

- **WHEN** 经 detectLanguage 或 detectLanguageWithSource 触发被禁用的 system 检测路径
- **THEN** 复用原本地算法并禁止 LLM，backgroundGenerateText 与 RPC 调用次数均为零，两个入口遵循同一引用优先级

#### Scenario: 直接 LLM 检测调用不进入尝试循环

- **WHEN** detectLanguageWithLLM 直接接收 system ref，或未传 ref 且配置为 system
- **THEN** 在原三次尝试循环前返回 null，生成和 RPC 调用次数均为零，由原消费者处理无 LLM 结果

#### Scenario: 显式非上游模型覆盖旧持久化选择

- **WHEN** 当前配置仍为 system，但调用方显式传入有效 local ref
- **THEN** 在各入口原有 LLM 开关和能力条件下保留该 local 检测路径，不因旧配置而强制降级或切换模型

### Requirement: 改动与上游同步边界可控

系统 SHALL 将新增功能代码放入 src/fork，复用现有模块重定向与指纹检查，不改上游翻译引擎、消息协议、配置 schema、迁移链或原 UI，不新增 allowlist 例外。预计上游原地新增改动仅限 wxt.config.ts 的注册增量；超出该边界 MUST 重新评审。

#### Scenario: 同步到被覆盖模块的改动

- **WHEN** 合并上游后被重定向文件移动、缺失或内容改变
- **THEN** 既有构建守卫阻止静默继续，维护者先检查差异、决定适配方式，再更新注册和指纹，不以批量刷新绕过检查

#### Scenario: 上游新调用路径引入

- **WHEN** 上游新增 RPC 方法、客户端或直接网络调用
- **THEN** 共用禁用出口的方法继续被拒绝；同步审查和网络回归必须检查新增出口，不能以无 Git 冲突或类型检查通过代替运行时验收

#### Scenario: 薄包装保持依赖与内部调用边界

- **WHEN** 冷启动导入 provider 或语言适配模块并调用其公开入口
- **THEN** 候选规则仅依赖纯身份叶子、原能力判断和类型，不通过配置/任译喵大模块产生新循环；需要协作的函数显式调用 fork 实现，不被上游模块内部词法调用绕过，原模型分类和配置同步算法保持不变

### Requirement: 隔离验收覆盖真实运行路径

系统 SHALL 同时提供加载 fork 重定向的契约/UI 测试及真实构建包网络验证，并保留原上游测试。验收记录 MUST 区分代码测试、构建和浏览器实证的状态。

#### Scenario: 双发行版构建和浏览器验证

- **WHEN** 准备验收本变更
- **THEN** 国内、海外 Chrome 测试及正式配置构建经过验证，既有三浏览器构建门通过；网络证据覆盖 Service Worker、扩展页面和 content script 的实际触发路径，并逐项回归页面、划词、输入、字幕、语言检测、自定义动作及自有登录能力；不具备账号/模型条件的项目明确待验收

#### Scenario: 外部测试明确跳过

- **WHEN** 本地测试设置 SKIP_FREE_API=true
- **THEN** free-api.test.ts 被明确记录为跳过，不被计作外部在线翻译服务验证通过
