# 上游云服务隔离设计

## Context

- 基线为 `change/fork-foundation@cc6a6597`，本变更在 `feat/disable-upstream-cloud-services` 开展。当前仅规划，不实施、发布或推送。
- 仓库已采用 `src/fork/**` 隔离、`setupFork()` 接入、`wxt.config.ts` 的 `FORK_UI_REDIRECTS` 构建重定向。解析器同时支持相对路径和别名，并检查源文件存在及内容指纹，不需要新增重定向框架。
- 现有 fork 已隐藏部分上游托管 AI、云转录和 Notebase UI，但后台初始化及两套 Auth/RPC 客户端仍存在；博客查询有弹窗和设置页两个运行时入口。
- 界面客户端通过 `backgroundFetch`，后台客户端直接 `fetch`；因此只改代理请求层不完整。当前 `WXT_API_URL` 已指向 fork 域名，不能按 `readfrog.app` 域名有无判断是否禁用。
- 图分析已确认 `setupHostedAiStatusHandler`、`setupNotebasePendingSaveProcessor` 的直接调用者为后台 `main`，博客查询有三个源码调用者（含被替换的上游弹窗）。这些局部入口风险为 LOW，不代表 Auth/RPC 动态调用链整体低风险；实施前补齐具体目标的影响分析。
- 既有 `fork-backend-repoint` 要求 v1 保留 better-auth 并让 fork 后端兼容，本变更通过 delta spec 明确取代该要求，不静默保留相反规格。
- 复审发现：旧 system provider 可进入普通翻译和语言检测链；语言检测有独立三次尝试；流式端口只传错误文本。仅拒绝 RPC 不能证明功能保留或无重试，必须在请求构造前处理旧引用。
- 图分析中 `isBuiltInAiProviderId` 为 CRITICAL、`computeForkConfigSync` 为 HIGH；两者不列入算法修改范围。Auth/RPC 动态对象结果为 UNKNOWN，必须结合调用点核对，不能以空调用集视为安全。

## Goals / Non-Goals

**目标：** 国内、海外所有运行环境不再从上游功能链路请求 `/api/identity`、`/api/rpc`、`/api/blog`；完整保留上游翻译核心和任译喵独立特性；让同步时的人工处理集中在注册表、薄适配层和契约检查。

**非目标：** 不增加能力平台、远程开关、持久化配置或依赖；不替代实现上游云服务；不删除旧配置；不修改自有接口域名；不全面清理其他上游服务；不将本次变更扩大为打包性能或 UI 重构。

## Decisions

### 1. 选择现有重定向加薄适配层

| 方案                             | 优点                                                   | 代价                                                 | 结论   |
| -------------------------------- | ------------------------------------------------------ | ---------------------------------------------------- | ------ |
| fork 薄适配层 + 现有构建重定向   | 上游原文件保留，调用方多数无需修改，契约变化有构建信号 | 每次同步要审查被替换模块                             | 采用   |
| 在上游调用点逐处加开关或删除代码 | 实现直观                                               | 改动分散，核心文件长期分歧，新增调用容易漏           | 不采用 |
| 仅隐藏 UI 或按域名阻断           | 初始改动少                                             | 后台请求、直接 fetch、重试和自有域名误伤无法妥善处理 | 不采用 |

不为三个恒定禁用的服务引入运行时能力开关。重定向清单与本规格就是本次策略边界；共享代码仅限重复的禁用错误和空状态，实际出现复用时再抽取。

### 2. 保持三条职责边界

```text
上游核心翻译逻辑 ── 现有 provider / SDK ── 任译喵网关或用户配置服务（保留）
任译喵自有特性 ─── src/fork/** ───────── 自有登录、会员、官网联动（保留）
上游云功能调用 ─── fork 禁用适配层 ───── 本地结束，不产生上游服务网络请求
```

上游“核心翻译逻辑”包括文本处理、翻译调度、模型调用、流式处理、页面/划词/输入/普通字幕翻译。上游“云服务”是其账号、托管模型与配额、云转录、云笔记及博客；关闭云服务不等于关闭所有 AI 功能。

任译喵继续通过现有会员 token/base_url 和 provider 接口接入上游引擎；自有功能继续放在 fork 目录，状态保持独立。新增自有接口不复用被禁用的上游 Auth/RPC 客户端，也不为其套兼容服务。

### 3. 关闭入口、触发与出口

| 服务     | 入口及后台策略                                                                         | 出口与结果                                                                  |
| -------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Identity | 隐藏上游账号入口；关闭上游会话订阅、刷新和登录诱导，保留自有账号菜单                   | Auth 适配器本地返回无会话、非加载状态；意外认证操作报告不支持，不清自有凭据 |
| RPC      | 保留已有托管 AI/云转录隐藏；补齐云笔记入口和引导；停用 Notebase 启动及 Cookie 变化处理 | 界面、后台 RPC 出口均本地拒绝，不构造业务成功结果，不网络回退               |
| Blog     | 弹窗通知和设置页更新入口均不挂载查询                                                   | 仅替换 `getLatestBlogDate` 的请求行为为返回 `null`，其他工具导出保留        |

RPC 保留现有 ORPC 契约类型和调用形态，通过本地禁用 transport 终止请求，不手写整个 router 模拟器、不用宽泛 `any` 假装兼容。前台的 `orpc` 查询辅助导出同样保留。

状态消息 `getHostedAiStatus` 仍注册并返回 `null`，不读取旧“可用”缓存、不查询服务器；同时保留 `clearHostedAiStatusCache` 的导出契约，满足现有代理层引用。`null` 在上游可能代表“无判定”而非拒绝授权，因此最终 RPC 禁用出口不能省略。

正常 UI 不挂载已禁用功能的查询；绕过请求前兼容仍触达云出口的调用必须终止为可识别的禁用结果，不能诱导购买上游套餐、无限重试或进入轮询。旧模型能够解析为合格 local provider 时按下一节继续正常执行。具体消费点若需要补充处理，优先使用已有 fork 壳或叶子适配器，不修改全局查询重试规则，不改变翻译引擎。

### 4. 旧模型只做请求前运行时兼容

不批量改写旧配置，也不在 RPC transport 内偷偷替换模型。先确定实际执行 provider，再构造参数、缓存标识和请求；最终 RPC 出口仍负责拒绝绕过适配的调用。

| 输入状态                                   | 运行时行为                                                                         |
| ------------------------------------------ | ---------------------------------------------------------------------------------- |
| 原解析器已返回有效 local provider          | 原样保留，遵循当前功能支持范围，不扩展隐藏模型入口                                 |
| 普通翻译或自定义动作引用旧 system provider | 按现有配置顺序选择首个启用、能力兼容且满足现有 key 条件的任译喵 provider           |
| 无合格候选                                 | 请求前结束，提示登录/选择模型；不新建 provider、不付费回退到任意第三方、不自动重试 |
| 语言检测引用旧 system provider             | 单独降级本地检测，不自动选择付费模型                                               |
| 笔记建议                                   | 当前 fork 无执行入口，保持关闭，不恢复也不分配替代模型                             |

`provider-registry.ts` 薄包装仅替换 `resolveProviderRefForCapability`，其他导出复用上游。同步候选规则只接收 provider 列表，不读 storage、不发请求、不刷新会员、不初始化 SDK；`isBuiltInAiProviderId`、`SYSTEM_PROVIDER_DEFS` 和能力分类原样保留。

候选 key 条件沿用现有任译喵门控语义，但 key 存在不等于服务端确认会员权益或剩余额度。真实调用仍走现有凭据、权限和额度流程；既有异步凭据获取留在原请求前边界，不塞入同步解析器。

`provider-ref.ts` 薄包装补齐已经解析为 system 快照、绕过 registry 的调用，在序列化/可用性检查时按同一规则处理；需要时只读取一次当前配置，生成真实 local ref 或本地不可重试结果，不再请求托管状态。正常功能必须更早取得最终 provider：已有 fork 划词、自定义动作和输入控制器在参数构造前消费解析结果，不能只替换请求地址。

实际模型必须统一用于提示词、模型参数、温度、缓存标识、统计和执行模型展示。持久化选择仍可保留旧 ID，但界面不得把上游模型标成实际执行者，也不能为更新展示隐式调用 `setConfig`。页面及字幕沿用原有“解析后构建缓存键”的顺序，不复用旧 hosted 身份缓存；显式旧引用转 local 不承诺命中原 system 专用会话快照缓存，不新增会话缓存机制。

### 5. 语言检测在三个入口前置降级

通过 `src/fork/upstream-services/language.ts` 重定向上游语言模块，复用原有本地 franc 算法：

- `detectLanguageWithSource`：显式 system ref，或未传 ref 且当前配置为 system，调用上游同入口时强制 `enableLLM: false`。显式有效 local ref 优先于持久化 system 配置，保留其原 LLM 行为。
- `detectLanguage`：显式调用 fork 的 `detectLanguageWithSource`，不能直接重导出原函数，否则其模块内词法调用会绕过包装。
- `detectLanguageWithLLM`：使用同样的引用优先级；禁用情形直接返回 `null`，在原三次尝试循环之前结束，其他 local 调用委托原函数。

验收必须同时断言禁用路径的 `backgroundGenerateText` 和 RPC 调用次数均为零，不以“最终没出网”代替“没有进入尝试循环”。此路径不写配置、不增加收费调用。

### 6. 错误与依赖边界

禁用采用独立错误码及既有 `isRetryable: false` 元数据；不得借用 `UNAUTHORIZED`、`HOSTED_AI_QUOTA_EXHAUSTED`、`HOSTED_AI_TIER_RESTRICTED`、401/403/404 或 `kind: access-denied`，避免误触发账号/额度提示或共享队列 `failQueue`，连带终止正常翻译。前端必须在请求前收敛禁用状态与 loading，不能依赖元数据穿过只传 message 的流式端口；直接 RPC 调用仍本地拒绝。不得改全局重试规则或扩展消息协议。

registry 包装不能导入整个 `src/fork/providers/renyimiao.ts`、UI gating hook、配置或状态模块，否则形成“registry → renyimiao → configSchema/DEFAULT_CONFIG/feature-providers → registry”循环。仅把已有 `RENYIMIAO_ID_PREFIX` / `isRenyimiaoInstance` 抽到纯叶子 `src/fork/providers/renyimiao-identity.ts`，原模块重导出以保持接口；候选规则只依赖该叶子、原 registry 能力判断及 provider 类型。不改变 `computeForkConfigSync`、种子或登录注入算法。

所有包装间的协作显式调用 fork 版本，尤其是 provider-ref 的序列化/可用性检查和语言函数。重定向允许包装复用原模块，但不会自动改写原模块内部词法调用；用冷启动导入及行为测试证明无循环和绕过。

### 7. 文件职责与预期冲突预算

以下为责任级文件布局，不预先铺设额外抽象：

| 位置                                                                         | 本次职责                                      | 同步维护方式                                     |
| ---------------------------------------------------------------------------- | --------------------------------------------- | ------------------------------------------------ |
| `src/fork/upstream-services/auth-client.ts`、`background-auth-client.ts`     | 分别适配上游界面和后台认证导出                | 对齐调用契约，避免后台引入 React 运行时          |
| `src/fork/upstream-services/orpc-client.ts`、`background-orpc-client.ts`     | 分别适配两套 RPC 导出；共用最小禁用 transport | 保留上游类型依赖，通过类型及拒绝调用测试发现漂移 |
| `src/fork/upstream-services/hosted-ai-status.ts`、`notebase-pending-save.ts` | 消息空状态和后台任务停用                      | 替换模块导出，不复制后台 `index.ts`              |
| `src/fork/upstream-services/blog.ts`                                         | 仅关闭博客请求导出                            | 复用其他纯工具导出，确认无模块初始化副作用       |
| `src/fork/upstream-services/provider-registry.ts`、`provider-ref.ts`         | 同步候选解析及显式旧引用兼容                  | 仅包装必要导出，不复制整个 provider 系统         |
| `src/fork/upstream-services/language.ts`                                     | 三个语言入口前置降级                          | 复用原本地算法及有效 local LLM 路径              |
| `src/fork/providers/renyimiao-identity.ts`、既有 `renyimiao.ts`              | 纯身份判断叶子与兼容重导出                    | 仅修改 fork，消除实际依赖循环，不改同步算法      |
| `src/fork/ui/**` 的既有入口及必要的叶子覆盖                                  | 隐藏云功能、博客通知和相应引导                | 优先修改已有 fork 文件；不整页复制               |
| `wxt.config.ts`、`src/fork/identity/redirect-baseline.json`                  | 新增重定向与已审查源文件指纹                  | 预计唯一新增分歧的上游文件是 `wxt.config.ts`     |
| `src/fork/upstream-services/__tests__/*`、`FORK.md`                          | 契约、无请求、合并验证和同步说明              | 沿用现有测试/文档机制                            |

本次不新增 allowlist 例外，不修改 `src/utils/host/translate/**`、`background-stream.ts`、上游消息协议、配置 schema、迁移链、模型常量或上游原 UI。文档与测试不构成新的运行时架构。

如果实施发现必须改上游核心、整页复制或扩 allowlist，应先停下来补充评审，不能以完成任务为由直接扩大边界。目标是“冲突范围可控”，不是承诺任意上游升级都无冲突或无行为漂移。

## 数据与接口契约

- 不新增数据库、storage key、用户配置或数据迁移。旧云笔记任务、用户自配 provider 和自有会员凭据均保留。
- 新增运行时兼容不持久化替代结果，不新增批量重指向；现有种子、登录及模型同步本来会更新配置，保持这些行为，不将“不新增写入”误解为禁止现有正常同步。
- Auth 仅实现已用到的会话读取/hook 等接口，并对其他操作明确拒绝；不初始化真实认证客户端产生订阅，不以不完整对象强制转换为整个 SDK 类型。
- RPC 禁用结果必须与正常成功、网络暂时失败区分；在需要的 fork 消费边界结束重试和 loading，不生成假数据、不回退到原客户端。
- 博客按既有 `Promise<LatestBlogPost | null>` 返回 `null`，无错误刷屏；禁用入口不读取旧缓存显示“有更新”。
- 精确范围为上游功能发起的三类端点，包括前缀本身及子路径。不是浏览器级路径黑名单，不限制普通网页或用户自配服务同名路径。
- `.env*` 中自有认证、claw、上报、官网、翻译网关配置保持不变；不以空域名、无效域名或删除必填变量表达禁用。

## 不定期合并上游的维护流程

1. 按现有 fork 流程进行 merge，记录上次和本次实际同步的上游提交；不要求固定同步频率，不假定本机已配置名为 `upstream` 的远程。
2. 上游核心保持跟随；`wxt.config.ts` 冲突仅保留 fork 插件接入及映射增量，其余正常合并，不整文件选一侧。
3. 对本次覆盖的模块和 `@read-frog/definitions`、`@read-frog/api-contract` 变更做定点检查。路径消失、内容指纹失配先读 diff，再决定调整适配器、解除覆盖或确认无需吸收；禁止直接批量刷新指纹。
4. 上游新增同一 RPC 客户端的方法仍由禁用出口终止；新增客户端、直接 fetch 或新 UI 入口需重新核对。指纹与类型检查无法证明所有新运行时路径均被隔离，必须复跑无请求验收。
5. 执行 fork 边界检查、上游测试、启用重定向的 fork 测试、构建和自有业务回归。零 Git 冲突不等于通过验收。

## 验证与交付

### 功能影响及验收边界

| 功能                     | 必须保留或关闭的行为                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------- |
| 页面、划词、输入/Discord | 非上游路径保持；旧引用运行时兼容，无候选前置提示                                                |
| 字幕                     | 现有字幕提取/翻译保留；摘要/分段须选用支持 LLM 的模型，不承诺纯翻译器具备此能力；上游云转录关闭 |
| 语言检测                 | 本地保留；有效非上游 LLM 保留；旧 system 前置本地降级                                           |
| 自定义动作、内置词典     | 生成能力保留；上游 Notebase 保存关闭                                                            |
| 笔记建议                 | 当前 fork 已无执行入口，不恢复、不新增生成调用                                                  |
| 自有业务                 | 登录、凭据获取、额度、模型、官网及上报沿用原链路                                                |

### 验证要求

- 契约测试：Auth 无会话且不加载；RPC 普通/流式调用均不出网；状态消息有响应；博客返回空；旧笔记任务不执行、不删除。分别监测真实 `fetch` 和 `backgroundFetch` 消息。
- 运行时兼容：未打开弹窗/设置/登录的冷启动、恢复旧配置、显式 system 快照、无候选、缺 key、禁用或能力不匹配候选；有效 local 不变，替代模型的参数/缓存/统计/展示一致，不命中 hosted 身份缓存。
- 语言及错误：三个导出的引用优先级、生成/RPC 零调用；禁用任务与正常任务并存，不误伤共享队列；覆盖端口丢失错误元数据的实际消费者，确认前置结束且无重试、无 loading 悬挂。
- 依赖与状态：冷启动模块导入无新增循环，内部调用没有绕过 fork；只验证新增兼容无配置写入，并独立回归现有种子/登录同步，不能通过关闭正常同步满足测试。
- UI 测试：挂载弹窗、设置页、划词功能及相关引导，既不出现云服务入口，也不发生查询/重试；自有会员菜单仍可用。不能只测试空适配器本身。
- 保留能力：覆盖上表全部功能，任译喵未登录、会话恢复、凭据获取/过期及额度异常沿用既有表现；回归 Discord 三空格翻译、修改译文后撤销、失焦再聚焦和语言菜单搜索。不以 key 非空替代服务端权限验证。
- 构建：国内、海外 Chrome 测试包和正式配置构建都必须验证禁用策略；沿用仓库 Edge/Firefox 构建门。正式配置验收不要求执行真实支付或产生收费副作用。
